## 1. Objective and governing constraints

Make focus, formatting selection, scoped input capture and reads, terminal disposal, optional-instance reconciliation, preparation, HTML publication, type ownership and verification obey explicit contracts. Repair demonstrated failures while preserving the union of legitimate v1 and current capabilities. Reduce repeated ownership transfers and exact forwarding APIs, not file count as an end in itself.

The implementation remains ESM JavaScript with useful checked JSDoc and genuine type-only facades. Runtime declarations are generated by `scripts/generate-declarations.mjs`; do not create shadow declarations beside JS to hide source diagnostics. Project JavaScript and behavioral TDD guidance applies, but generic syntax preferences do not override synchronous completion, original method receivers, accessor capture, owning DOM realms or cancellation.

Retain `DocumentStore`, `DocumentDraft`, `PersistentBlockMap`, `TransactionEngine`, `HistoryStore`, existing planners and scoped extension lifetimes. No second model/history/selection store, universal command bus, global authority manager, generic media manager, collaboration engine or framework wrapper is introduced. A large file is not sufficient evidence for decomposition.

The target is current-only: no old runtime, compatibility adapter, deprecated alias, old-format decoder, migration chain or permanent dual API. Existing current documents retain document `version: '2.0.0'`, exact registered `dataVersion`, IDs, order, tunes and sidecars. Preserving this current data contract does not require accepting v1 wire data.

## 2. Scope and preservation

### 2.1 Required preservation

- **P00 — union:** preserve legitimate v1 capabilities plus legitimate current capabilities and intended defect repairs. A broken baseline does not define the desired outcome. Code injection, data loss, foreign-editor interference and unauthorized continuations are defects, not capabilities.
- **P01 — canonical authority:** save reads the accepted model; planners, DOM and caches do not become alternative stores. Nested supported commands read the active draft.
- **P02 — action/history:** one completed semantic gesture is one history action; recognized canonical no-ops create none. Preserve Undo/Redo, grouping and qualified metadata continuation. Explicit render/clear replacement keeps its generation/history semantics even for equal content.
- **P03 — data:** retain valid current records, exact versions, stable item/field identities, own dictionary keys including `__proto__`, ordering, marks, tunes, literals, inline references and opaque unloaded-extension payloads.
- **P04 — interaction:** preserve caret, direction, local/cross-block selection, clipboard, conversion, split/merge, native input and composition confirmation/cancellation. Do not replace genuine DOM/native proof with mock totals.
- **P05 — occurrences:** rights belong to exact instances, tasks, tools, panels and popup presentations. Reusing a serialized ID does not revive a retired owner.
- **P06 — selective cancellation:** read-only round trips, replacement and disposal revoke affected work; an unrelated block edit does not automatically revoke a valid task.
- **P07 — recovery:** failed preparation/projection cannot publish an accepted edit or partially move history. Recovery failure is explicit; accepted commits are not retroactively undone by observer errors.
- **P08 — resources/realms:** preserve ownerDocument/window, styles, listeners, URLs, staged acquisition and cleanup. Editor terminal disposal and reusable renderer-output disposal remain different lifecycles.
- **P09 — extension capabilities:** retain all 21 blocks, 12 default tools, both inline plugins and third-party declared capabilities. Core routes by neutral contracts, not built-in names.
- **P10 — packaging/output:** preserve synchronous/selective/asynchronous loading, installed-package consumers, generated declarations, renderer revision reuse, supported engines and output resources.
- **P11 — extensibility:** a replacement preserves the whole capability, including public subclass/override behavior, not just the most common constructor call.
- **P12 — presentation:** retain supported classes, typography, targets, navigation, downloads, media, layout and host styling. Security work must supply a safe semantic equivalent, not silently remove a useful behavior.
- **P13 — proof:** no unexecuted, skipped, historical or exploratory result is candidate acceptance. Every meaningful capability discovered later extends the open preservation register.
- **P14 — completion:** task settlement, model change, history grouping, cancellation and occurrence retirement are distinct. Successful replacement can abort the old task signal without reversing a true commit result.

Only three difference classes are accepted: defect repaired; API relocated with equivalent capability; representation changed with preserved semantics. There is no feature-removed-for-security/refactor/simplicity category. A material conflict between useful baseline behaviors blocks the affected design until resolved; choose neither baseline merely because it is easier.

Test-only adapters may translate incompatible v1/current API and wire spelling. They must not normalize away meaningful text, marks, order, filenames, identity, selection direction, action count, provider effects or resource ownership. No test adapter ships as product compatibility code.

### 2.2 Non-goals and evidence

Do not invent CommonJS support, an all-TypeScript rewrite, generic field patch/enumeration API, host media allowlists, capacity defaults, retry policy, universal latency SLA or authenticated publishing platform. Do not make all callbacks asynchronous or hold a transaction open for an observer Promise.

The baseline has four source type diagnostics, eighteen failures in a 1753-test full run, and separately demonstrated browser defects. Failed tests include incomplete test doubles and cascading build failures; they are not eighteen independently established user regressions. The publication review distinguishes fresh runs from inherited browser evidence. Full v1/native/IME/system-clipboard/Firefox/WebKit/heap acceptance is not established.

| R03 | Script modes use their panel continuation, preserve selection and author once; stale panels cannot affect successors. |
| R04 | Raw/Carousel HTML cannot execute active code or cover unrelated host UI; legitimate reader and presentation capabilities remain. |
| R05 | Inline safety does not silently strip accepted styling, targets or typography. |

| R09 | Configured serialized history bytes are bounded with an explicit newest-record exception; replay does not discard accessible actions. |
| R10 | Evidence identifies actual source and executed command; skipped gates cannot inherit historical logs. |
| R11 | Corrected source passes applicable type/build/unit/source/docs gates without suppressions, skipped regressions or fabricated DOM fallbacks. |
| R12 | Performance improvement is measured on complete paths and retained memory without unsupported absolute promises. |
| R13 | A settled failed editor can be publicly disposed exactly once while failed authoring remains forbidden. |
| R14 | Rejected scoped calls do not read caller options; admitted options are captured once under preparation before producer dispatch. |
| R15 | Completion, data change, grouping and abort state are independent; deferred host commands use current admission and stale tokens remain stale. |

**I01:** only the canonical transaction owner accepts persisted edits. **I02:** admission precedes producer/input code and is revalidated across callback boundaries. **I03:** published immutable values do not become mutable shared aliases. **I04:** occurrence identity is stronger than serialized ID. **I05:** one observable action has one coordinator, not another store. **I06:** proof uses independent expected behavior and honest provenance. **I07:** admission metadata cannot execute with greater rights than the requested operation; disposal is distinct from authoring. **I08:** cached inline data never advances as if a missing hook updated the DOM. **I09:** failure presence is independent of thrown value. **I10:** standalone view refresh owns no document/history commit and cannot borrow an old transaction rollback.

## 4. Architecture and decomposition

| Owner | Responsibility | Excluded responsibility |
|---|---|---|
| DocumentStore/Draft/PersistentBlockMap | Accepted records, order and active draft | DOM, observers, plugins |
| TransactionEngine/HistoryStore | Existing atomic commit/recovery/replay and history retention | New UI state or broad asynchronous rights |
| DocumentRuntime | Admission, protected preparation/reads, current-draft capture, private-handle checks and applying plans | Browser clipboard I/O or a second model |
| CanonicalTransforms/Ingestion/range/clipboard/conversion planners | Owned values and prepared edits through narrow services | Connected DOM, selection managers, history, runtime commands or publication |
| ClipboardFragment | Pure current wire codec | ClipboardData, mounted DOM, store or controllers |
| BlockReconciler/InlineProjectionRuntime | Block and inline mounted ownership, projection and originating-operation recovery | Independent document acceptance |
| InteractionState/EditorViewModel | One focus/current intent and its presentation coordination | New logical-selection store |
| LogicalSelection/SelectionController/InlineSelectionAuthority | Coordinate conversion, gestures/highlights, scoped formatting capability respectively | Three competing persisted selections |
| InlineToolbar/tool mounts/panels/popup host | Their separate leases, presentation and teardown | Interchangeable lifetime tokens or separate document persistence |
| Shared canonical type/schema owners | Neutral data vocabulary and schema validation | Renderer-owned document model |
| EditorRenderer | Read-only output ownership, registration, revision reuse and disposal | Editing engine or history |

Keep NativeInputController, KeyboardRouter and InlineWidgetInputController distinct where their protocols differ. Do not merge Poll author configuration with live results, Person canonical cards with active-card presentation, or Carousel media/session ownership with arbitrary HTML confinement. Existing large modules are not automatically split. A local helper is justified only by coherent responsibility or shared acquisition logic, not mocking convenience.

Runtime, type/JSDoc and callback-port dependencies all matter. No runtime import cycle is necessary for an authority leak. A closure created by runtime may call a protected pure value operation; the architectural violation is granting a planner write/control/publication authority, not the mere presence of a closure.

## 5. C01 — focus intent and native acknowledgment

**Owner:** InteractionState intent/current publication, with existing EditorViewModel and reconciler presentation. **Consumers:** public focus, keyboard/selection and command continuations, third-party BlockInstance.focus.

Keep public `blocks.focus(id?, target?): boolean`, `editor.focus(): boolean` and plugin `focus?(target?: FocusTarget): void`. No public intent token or parallel focus API is added. Capture target values under preparation before effects and recheck control authority. Do not add unrelated unknown-key or integer-only validation.

Preserve absent/default targets, `start`/`end`, finite fractional numeric offsets truncated to logical UTF-16 positions, and clamping to the field range. Baseline examples are 2.9→2, -2→0 and 1000→5 for a five-character field. Strict extension bookmark restoration is different and must continue rejecting stale/out-of-range continuations rather than clamping them.

A keyed request means that field, not a fallback first field. A plugin may reveal a hidden tab/card/slide field before its descriptor is mounted. Do not pre-reject solely on the current mounted descriptor list or introduce a generic field-enumeration API to do so.

One synchronous operation:

1. Validate authority, capture input and prior valid focus/selection, then obtain an interaction intent before plugin focus.
2. Capture destination occurrence, generation/revision, mode epoch and intent identity. An admitted explicit navigation decision is a newer intent even for the same block; a forbidden attempted reentry is not.
3. Invoke existing plugin focus under presentation protection. It may reveal UI but not author model data.
4. Native focusin from that exact destination during the operation is provisional acknowledgment, not a new setCurrent decision. Intermediate same-occurrence focus while revealing the field stays provisional.
5. Native focus to another owner, admitted successor navigation, replacement, mode change, health failure or teardown invalidates the old request.
6. Resolve the requested live field after disclosure, place the logical caret, and revalidate after native callbacks.
7. Publish currentId only after the target is secured. Emit at most one current-block change for an actual accepted change; repeated focus in the same current block emits none. Toolbar follows the accepted result.

Unknown/missing target, failed plugin focus or failed caret placement returns false without provisional current/selection publication. Restore a prior owner only while that owner and intent still remain valid. A superseded request returns false without stealing the successor's selection. Once acceptance was published, a listener may legitimately create another navigation decision; its later supersession does not erase the earlier accepted event. Destroyed/forbidden-phase calls keep fail-fast exceptions before effects.

Stable read-only mode does not acquire a new blanket navigation ban. Focus never grants editing rights. Failed recovery of focus cannot fabricate success; contain unexpected errors through existing content-free diagnostics. The host does not generally undo arbitrary plugin disclosure, but built-ins validate recognizable invalid keys before unrelated UI changes. Native focus outside a request remains a normal interaction input. Do not use global event suppression or isTrusted alone to identify acknowledgments.

## 6. C02 — logical range correspondence and formatting

**Owners:** existing logical codec/reconciler and InlineSelectionAuthority. Retain opaque bookmarks, `range`, `capture(range?)`, `restore(bookmark, options?)`. A returned Range is a fresh view, not a durable DOM address.

A point is `(blockId, fieldKey, offset)` for a current occurrence. Preserve the existing textOffset model: UTF-16 units, one unit per BR/atomic widget, no caret-padding/control/nested-editor text. A strict formatting endpoint cannot split a surrogate pair. Generic formatting cannot address a widget label.

Authorization requires matching ordered logical endpoints, exact editor/realm/occurrence/field ownership, connected visible writable eligible endpoints and a live lease/generation/revision after callbacks. Parent boundaries around the same author text and equivalent empty wrappers are valid. A numerical offset coincidence inside a widget/control is not. Complete widgets between eligible external endpoints remain atomic.

Compare ordered Range endpoints for correspondence and retain authoritative anchor/focus direction separately. Exact compareBoundaryPoints equality and equal selected strings are both insufficient. A missing method in a test double is not permission to accept an otherwise unproved range.

A genuine native selection change outside the owning protected mutation expires the token immediately, including before queued selectionchange. Wrapper transformations within that one protected mutation may restore captured logical points at the current revision. `endOffsetDelta` remains a finite integer applied to the original DOM-order end in its field, not cumulatively; nonzero delta is allowed only inside the owning protected mutation and cannot rebase a stale token. Out-of-bounds or reversed results reject. After commit, only the actual accepted operation may refresh its completion; old bookmarks remain stale.

Invalid pre-mutation capture/restore has no producer, focus, highlight or document effect. Required restoration failing after a transform starts aborts through existing projection/selection recovery, not a partial formatting commit. History's own structural fallback/reveal policy remains separate from strict extension restoration.

## 7. C03 — panel continuation

**Owner:** InlineToolbar panel lease; consumers include Script modes. The mounted tool port remains for direct mounted actions.

Keep existing InlineToolActionContext members, including range, mutate, restoreSelection, close, localization, alignment and tooltip. A Script action must inspect, mutate and restore through its panel context throughout. Do not capture a panel Range with the mount's `cbs.capture`, restore it with mount `cbs.restore`, or restore old offsets after closing.

Within `ctx.mutate`, removal and application of sup/sub wrappers use the supplied authorized range and `ctx.restoreSelection()` as necessary. A failed required restoration aborts. A semantic change is one action; a no-op is none. Successful close uses the refreshed result of that operation.

Panel retirement/replacement, mode round trip, document replacement, superseding selection, occurrence retirement and destroy reject retained callbacks before producers. A stale button cannot borrow a current panel's lease or close it. Link Apply/Enter are passing preservation controls; do not rewrite them merely because of similar identifiers. Mounted color/font popovers remain mount-owned unless a separately grounded contract changes that fact.

## 8. C04 — prepared values and dependency fitness

### 8.1 Preparation contract

Keep synchronous flow: admitted public/controller input → guarded capture → current TransactionEngine draft → protected planning over captured draft view → owned edits/result → existing projection/commit/publication.

A planner must see earlier edits in its surrounding draft, not a newly read committed snapshot. Use the existing session allocator; failed reservations are not recycled or replaced with local counters. The internal plan is `{edits: readonly PreparedEdit[], result}`, where an edit is insert(index, record), update(id, record) or remove(id). Records use the existing canonical EditorBlockData envelope, not another wire model. Preserve direct move/replacement operations; do not synthesize remove/insert for them.

Validate complete plan shape and owned schema-valid records before applying edits. Empty edits means no authored change. Planning output is not a durable lease: existing private clipboard handles still check captured source identities/order when applied.

Declare narrow checked JSDoc ports for actual canonical readers, captured schema/capability lookup, normalization/assembly and allocation. Do not pass runtime, engine, history, view, event bus, mounted nodes, native selection or public command functions. Detached parsing templates in an explicit ownerDocument are allowed. Extract pure algorithms only when that creates a real boundary; forwarding the entire runtime through command objects is forbidden.

The preparation guard covers accessors, iterators, callback completion, result inspection and ownership capture, and exits in finally. Reject Promises/callable thenables through existing synchronousResult rules. Preserve captured receivers. A preparation callback cannot author, navigate, change mode, acquire a task or destroy the owning editor through reentry.

Public input rejection before dispatch is distinct from failure inside an entered transaction. A failed entered nested mutation poisons the outer draft even when its falsy throw is caught. Do not retry within a poisoned draft.

### 8.2 Canonical types and source checks

Keep document/block/inline envelopes in `shared/documentTypes.d.ts`. Move built-in payload/item types, BlockType and their typed union to a real neutral type-only shared owner aligned with schemas. Renderer config, DOM-output ownership and companion-renderer callbacks stay renderer-owned. Core/plugin loaders must not depend on renderer declarations for canonical data vocabulary. A companion Mention/Color output renderer may use renderer contracts legitimately.

Repair the four baseline diagnostics at canonical sources: include emitted `cut.failed` in EditorDiagnosticCode; use a literal-kind clipboard part union and narrow before html access; express post-callback InstanceScope state as a live query without deleting the revocation check. Repair missing test imports and incomplete doubles independently of behavioral fixes. No blanket any, suppressions, skipped regressions or mock-driven production fallback.

Strict-check changed boundary ports and public consumers with focused strict configuration while preserving full runtime checkJs. Whole-project strict migration is not silently included. Change canonical JS/type-only sources and regenerate dist declarations; do not edit generated output as authority.

### 8.3 Architecture checks

Extend existing source-audit machinery, not a new framework. Neutral values/schemas/types depend on neutral values and platform parsing primitives, never editing or renderer runtime owners. Pure ClipboardFragment owns JSON wire validation and may be used by preparation; it has no ClipboardData, mounted DOM or engine dependency. Planners may use captured capabilities but not authoring/publication. Extensions use published plugin-kit/neutral contracts, not private core. Read-only renderer has no editing-controller/transaction dependency.

Check static/dynamic imports, JSDoc/type queries, self-package imports and generated entrypoints without treating comments as executable edges. Include a negative planner→runtime control and a positive pure-codec control. Do not split a validator solely to accommodate the old filename allowlist.

## 9. C05 — safe embedded HTML with preserved capabilities

**Blocked by B-HTML and overlapping B-STYLE.** Required outcomes are normative; a particular iframe/containment topology is not yet selected.

Affected surfaces are Raw editor preview, Raw renderer, HTML Carousel slides in editor and renderer, with shared sanitizer and existing style/lifecycle owners. YouTube/Vimeo embeds are a separate capability.

Reject active code, host-covering content, forged host controls, unauthorized navigation/focus and stale resources while preserving legitimate source editing/indentation, preview, links including local fragments and permitted targets, downloads, native media controls and browser-permitted playback, text/marks, theme/class styling, relative URLs, responsive sizing, reachable tall content, accessibility/keyboard behavior and Carousel controls. Update/Undo/Redo and disposal remain coherent. Preserving href in JSON while making its displayed link inert is not equivalent functionality.

Do not rewrite canonical author data to accommodate a narrower view. A small scrolling frame is not automatically equivalent to normal document flow. Work under injectStyles:false, explicit ownerDocument and supported CSP/Trusted Types; do not weaken parent policy or fall back to unsafe same-document insertion. Serialized content cannot grant trust/sandbox flags. No safeRaw/legacyRaw modes.

An opaque sandbox prevents capabilities independently of sanitization; parent measurement and inherited styles are not automatically available. Shadow DOM is not an equivalent security boundary. Unrestricted script/same-origin/top-navigation flags or copying arbitrary host styles is not an accepted shortcut. The old non-navigating fixed-viewport proposal is withdrawn, not approved as a compatibility break.

**E-HTML investigation:** use isolated real-browser fixtures for linked/themed long content and mixed-media Carousel plus malicious overlays/injection. Compare materially viable confined designs with trusted navigation/download/pointer/keyboard input and network observations. Settle navigation/local fragments/download filename authorization, style/theme ownership, resizing, resources/credentials, Carousel input and stale-surface revocation. Test strict parent CSP/Trusted Types, failure and disposal. Stop when one current-only contract has demonstrated both safety and decisive benign preservation, or document a concrete incompatible requirement needing an explicit decision. Amend C05 before dependent production; discard or freshly review prototypes, not two product modes.

DOMPurify maintenance is separable only after current official version/advisory verification and malicious plus benign corpus, lock/license assertions, owning realms and Trusted Types checks. The inherited review verified release 3.4.17 on 2026-10-12; do not call that a fresh advisory check at every later implementation. An upgrade alone does not prove UI confinement.

## 10. C06 — presentation-preserving inline safety

**Owner:** shared inline sanitizer/normalizer. Preservation is settled; destructive new trust policy is blocked by B-STYLE.

Keep supported inline properties color, background-color and font-size, URL protections, required rel handling, code lang/highlighting and sidecar/token boundaries. Do not add arbitrary new CSS properties. Validate using the owning realm and preserve neighboring legitimate text/marks when rejecting unsafe attributes.

Do not blanket-strip span/code classes, force all targets to self/blank, restrict persisted sizes to the integer 1–200px UI range, or delete relative/fractional/calculated/inherited/theme-dependent sizes. The preservation corpus includes 16px, 16.5px, 1.5em, 150%, 1.5rem, calc(10px + 1em), 201px, 250px, inherit and benign article-accent classes. Canonicalization may change equivalent spelling, not presentation meaning. Attribute survival is not proof of actual target navigation; test controlled permitted destinations, including platform noopener behavior.

Case-insensitive checks are not a replacement for CSS grammar and must not reject arbitrary benign identifiers. Do not weaken JSON ownership, sidecar identity or parent CSP in the name of preservation.

**E-STYLE investigation:** compare benign theme/class/target/typography and malicious host-class collisions. A generic sanitizer cannot infer the host's semantic class vocabulary. Determine whether existing configuration supplies a justified trust input before inventing a public option. No default allowlist, numeric cap or content-controlled trust switch is assumed. Settle one policy preserving positive cases and blocking the demonstrated threat, then amend C06. Independent non-destructive defect fixes do not wait for this decision.

## 11. C07 — phases, scopes, recovery and publication

### 11.1 Separate dimensions and rights

Retain phase, generation, revision, mode epoch, occurrence, tool/panel/popup lease and focus intent as separate dimensions. Share predicates only when their revocation semantics match. Do not replace nested preparation/observation depth with a boolean.

Type the existing engine phases: idle, preparing-metadata, capturing-selection, building, preparing-projection, applying-projection, committing, finalizing, publishing, diagnostic-observation, failed. Runtime preparation, validation observation, protected DOM edit, presentation projection and mode transition are invocation contexts, not serialized states.

| Context | Rights |
|---|---|
| Healthy idle | Supported host writes, including stable read-only host updates; user/plugin writes additionally require editable live ownership. |
| Building | Supported nested commands compose in the current draft; entered failure poisons it. All protected-context checks still apply. |
| Input/extension preparation; validation/diagnostic collection | Accepted-state queries only; no owning-editor public write/control/DOM action/teardown/task acquisition from that callback. |
| Projection prepare/apply/finalize; presentation projection | Only the owning internal operation's projection/cleanup; no public reentry or task acquisition. |
| Protected DOM action | Only that admitted callback and its own restoration; unrelated commands cannot borrow its rights. |
| Publishing | Accepted model/history readable; synchronous reentrant public write/control/task acquisition denied. |
| Mode transition | Affected continuations revoked before fallible UI notifications; no nested public mode/write. |
| Failed | Accepted data readable by existing query policy; no edits/replay/ordinary controls; settled disposal allowed. |
| Destroyed editor handle | Existing live guards reject; repeated destroy is inert. Renderer-output disposal remains reusable. |

A focus-only event emitted in healthy idle is not automatically transaction publication and may admit a successor under C01. Task begin/commit require active same-generation healthy editable idle ownership. No retry, implicit queue or fallback task is introduced.

### 11.2 Commit and fan-out

Keep build draft → prepare projection → apply → prepare history/event → commit model/history → finalize → publish. Success-determining fallible work is pre-commit. Recover/discard pre-commit failure and restore valid prior selection without new history/events; failed recovery is terminal. Commit-swap failure is not an ordinary no-op. Do not introduce user callbacks, schema work, JSON traversal, byte accounting or diagnostics into the small prepared swaps.

Post-commit finalization/observer containment never reverses accepted canonical state. Preserve fan-out order: revoke stale clipboard continuation, reconcile interaction, refresh toolbar, schedule coalesced change notice, transaction:committed, document:changed, history:changed. Attempt independent steps despite earlier failure. Diagnostics and timer failure are contained and content-free. Public history availability reflects mode/health, not only stack nonemptiness.

Share owned immutable change subtrees across event envelopes only through internal provenance. Envelopes remain deeply immutable; external Object.freeze is not a trust mark. No mutable history escapes and no event-driven second authoring loop is added.

### 11.3 Settled terminal disposal

DocumentRuntime owns admission; EditorHandle.destroy requests existing lifecycle cleanup. After protected failure unwinds, settled engine failed phase and failed control health both allow destruction, not authoring. The allowFailed health exception must not be defeated by an unconditional idle/building phase check. Active preparation, observation, DOM edit, projection, publication and mode callbacks still deny public teardown; their effective protected context takes precedence.

Mark destroyed before external disposers; independently attempt cleanup, retire continuations and release holder lease. Repeated destroy is inert. Do not reset health, retry the edit or recreate an editor. Normal destruction removes owned resources but does not gain failed-construction's obligation to restore original holder children.

### 11.4 Scoped option capture

InstanceScope owns task reservation/retirement; runtime owns preparation; context adapters own conversion to command input. Public task/inline shapes remain unchanged.

For DataTask.commit: inert typeof producer validation; reject closed/consumed/reserved/aborted locally before option reads; reserve the invocation before callback-capable admission; check active parent/effective mode/health/epoch/generation/phase with revalidation; capture only mergeWithPreviousField once under preparation; revalidate; dispatch through existing transaction; release reservation in finally.

Recursive commit on the same reserved task returns false without stealing the outer call. Unavailable ownership closes/aborts and returns false. A forbidden active phase throws before option access without consuming a still-live task. Preserve absent/null option behavior and existing supported property lookup; the optional field remains an absent or nonempty string with existing 128-code-unit bound. Do not enumerate unrelated properties or invent a new options-shape restriction.

A normally returning getter that cancels/revokes leads to false and no producer. Input/getter failure propagates and leaves a live task retryable unless independently retired. Entered producer/transaction failure consumes/aborts. A valid result, including canonical no-op, consumes. Preserve supported nested author composition inside the admitted producer; preparation is not authoring.

For inline updateData, initial retired-owner no-op rejection precedes any options. Capture trailingText once under the same preparation owner, then recheck scope before producer/dispatch. Keep its void result and existing validation; no unrelated public option is added.

Supply a narrow internal synchronous value-preparation port `(operation: () => T) => T` from production runtime to scope/adapters. No scope import of DocumentRuntime, exposed plugin port or silent unguarded production default for mocks. Capture includes returned accessors and ownership work. Argument expressions evaluated before API entry are outside this guard. Trusted plugin JS is not sandboxed; another independent editor keeps its own rights. Aborting local work does not roll back a completed remote upload.

### 11.5 Task completion and history hint

True means an admitted task completed, not necessarily changed data or merged history. A canonical no-op consumes with no new revision/event/history. False from a closed/busy/retired call invokes no option getter/producer. Input failure remains retryable; entered producer failure does not. Cancel is idempotent, does not roll back accepted state and need not change an already-successful consumed task's signal.

Signal.aborted is not a consumed-state flag. Successful projection replacement may retire the committing occurrence and abort its signal before commit returns true. Never retry, turn this result false or keep old rights alive to make the signal look un-aborted. In-place/no-op/unrelated changes retain other valid tasks.

mergeWithPreviousField is a narrow optional block-history hint, never a guarantee. Preserve positive captured revision; immediately eligible predecessor; prior origin native-input/plugin and name native-input/block.update; completion name block.update; exactly one same-block update each; own top-level field present in all four records; field changed previously and unchanged by completion; canonical equality of predecessor-after and completion-before; coalescing allowed and empty Redo. An explicit gesture/replay boundary seals it. Incompatible intervening accepted actions prevent merge; queries/no-ops do not automatically imply a boundary. Inline tasks remain independently undoable under this hint. Do not invent inline grouping as a repair.

### 11.6 Deferred observers

### 11.7 Read-only recovery

If any fails, restore committed projection through the existing owner. Successful restore retains previous mode and original forward failure without history. Restore failure is a recovery-classified aggregate with real failure values; runtime becomes failed, accepted data remains readable, settled disposal stays available.

Do not roll back modeEpoch to revive old tasks or remount ordinary successful mode changes. Include paired block/inline falsy and Error controls and secondary restoration failure, not just the initial counterexample.

### 11.8 Protected inline reads

Runtime owns guarded inline decode/read; scope keeps pre/post lifetime checks; schema snapshot keeps exact version, synchronous result and JSON ownership. Keep getData(): Readonly<D>.

For a live or legitimately staged readable instance, enter preparation before invoking decode and reading/capturing its result. Complete ownership before leaving; retain generation/readability checks before and after. Read-only alone does not forbid reading. A revoked occurrence fails before decoder execution. Nested synchronous owning-editor write/control/task attempts from the decoder fail before producer. A decoder that catches that denial and returns valid data may still produce a read if its owner remains valid. Do not return raw serialized data instead of decoded data or globally suppress legitimate later host commands.

### 16.5 B-PRESENTATION — settled field recovery contract

**Decision settled, 2026-10-29; implementation acceptance requires the proof below.** Standalone presentation refresh is owned by BlockReconciler and InlineProjectionRuntime, under DocumentRuntime's existing presentation guard. Accepted document data remains authoritative. The settled-attempt contract below applies after editable descriptors have been captured and structurally validated, to the known inline decode/acquisition/update projection path. A descriptor hook that throws before returning a descriptor set, an invalid descriptor shape, or initial ownership validation failure retains its existing boundary failure; no same-set failure memo or retry guarantee is claimed for that absent/invalid set. The observer still reports each such actually delivered failure and continues independent B deliveries. A capture/initial-validation failure does not preserve authoring rights for a previously accepted field that meanwhile lost its owner: retire those old field/inline scopes, including losses caused by cleanup callbacks, while returning the original pre-admission failure. This retirement does not create a settled retry memo for the absent or invalid new descriptor set. Recovery is scoped to affected field occurrences; replacing the entire block is not the default recovery for a field fault.

#### Admission and preservation

A presentation attempt captures the plugin's descriptor set once. A descriptor is the exact `(blockId, fieldKey, mode, HTMLElement)` association under the current owned block shell. Previous accepted field-owner leases and their exact editable/widget/control/block owner paths remain evidence of ownership; matching IDs, CSS markers, `contains()` alone, or a failed-attempt memo do not authorize a field after adoption into another owner. Harmless layout wrappers are transparent when the same exact field and owner boundaries remain; this does not weaken the separate exact detached-widget ancestry proof. Ownership is revalidated after extension creation/update and cleanup/destroy/disconnected callback boundaries, before publication, on subsequent queries, and before restoring a field's enabled state. An unchanged healthy descriptor query validates and reuses its existing lease; it must not republish a freshly captured ancestor path to accept adoption. If that existing owner is lost, revoke its field and inline scopes before returning the failure. Any per-call ancestry lookup is discarded before cleanup callbacks and rebuilt for the next validation pass.

An unchanged healthy sibling field retains its DOM nodes, native selection/range, inline instances, contexts, signals, and valid DataTasks. The host must not normalize, hydrate, call extension hooks on, or retire that sibling merely because another descriptor changed or failed. Removed or changed field occurrences remain affected occurrences and may retire. A callback that moves a formerly healthy field into another editable/widget/block owner makes that field affected; its old authoring lease and inline scopes must be revoked, not silently retained.

Preservation uses existing ownership and canonical data, not another canonical store. The ordinary healthy-field check compares a readonly author projection against the current accepted rich-text value: genuine privately owned inline/opaque roots are represented by their canonical tokens, and their internal widget DOM is excluded from author markup. Unsafe author elements/attributes, forged widget markers, and unowned editing islands cannot obtain preservation through sanitized-copy equality.

Pending native author DOM is a separate admitted case. NativeInputController may supply a readonly observation of its existing trusted `beforeinput` envelope, active composition session, or ending composition session. It must match the exact previously accepted field element/address, current generation, revision, mode epoch, connected editor ownership and live controller; a prevented, synthetic, stale, foreign or retired envelope grants no preservation. A trusted composition start owns the session; an engine-produced composition end need not independently mint a new authority token. Safe author DOM and genuine private widget leases are still checked. This observation grants no model mutation, history, rebase or new instance authority. The existing native owner alone settles the pending edit. Arbitrary DOM text without that envelope, unsafe live markup and forged widget roots continue through canonical repair.

#### Attempt, failure and query outcomes

A successful attempt publishes only complete, currently owned descriptors and coherent inline state. A registered decoder failure is a failure, never successful publication of literal placeholder text. Preserve its original thrown value/object and schema classification. Unregistered types remain independently successful opaque occurrences; literal author text remains a third case.

On an ordinary field acquisition/hydration failure, retire the failed/changed field's provisional and superseded inline occurrences exactly once. Do not revoke healthy siblings. Revoke failed field authoring leases, clear incomplete host projection while that host is still provably owned, and disable that host. Keep accepted data and sidecars intact. Retained field publication reuses the captured healthy leases; it cannot recapture a foreign ancestor path after cleanup callbacks. Revalidation may only shrink the retained set, without another acquisition. Store the settled attempt result on the existing block entry; this is a presentation result, not accepted canonical content or a second ownership registry.

| Entry point or state | Required observable result |
| --- | --- |
| First synchronous query that discovers the failure | Throw the original failure after containment. Do not return the failed descriptor. Report the attempt once through the existing runtime observer/diagnostic owner. |
| First asynchronous observer delivery | Contain A, report that attempt once, and continue every independent valid block delivery in the same batch, including B. Do not use an uncaught window error as the reporting contract. |
| Later query for the same settled failed descriptor set and unchanged failed canonical content | Revalidate the remaining healthy leases; return only complete healthy descriptors. A failed key is absent/undefined. Do not call its decoder/create/update hooks or emit the same diagnostic again. |
| A retained healthy lease becomes invalid after settlement | Revoke its field authority and inline scopes. The discovery reports a distinct containment/ownership failure; later queries must not resurrect that lease. Preserve still-valid unrelated fields and blocks. |
| A new explicit presentation changes descriptor identity | Permit one fresh acquisition attempt through the existing owner. A new failure is reported for that attempt. Revoked occurrences/scopes remain revoked. |
| Repeated automatic notifications or repeated queries | They are not retry permission. There is no timer, backoff, retry counter, scheduler or new public retry/quarantine API. |

The reporter belongs to DocumentRuntime: use its existing protected validation callback for the original schema issue and its existing content-free `command.failed` diagnostic with operation `projection.presentation` and error name. Do not add document text, sidecar payloads or error messages to diagnostics. Synchronous callers additionally receive the actual original thrown value. Observer callback errors remain isolated by the existing observation boundary. Failure presence must not depend on the truthiness of a thrown value. An observer callback suppresses a duplicate report only when this exact delivery published or changed the contained result and its reported error matches the thrown value. An absent or unchanged memo cannot suppress an actual descriptor-hook failure, including undefined/null/false or a separately delivered rethrow of the same earlier Error object.

#### Recovery failure and terminal ownership loss

If containment itself fails, throw an AggregateError preserving the first failure as `cause` and retaining both failures; asynchronous delivery reports this declared outcome through the same runtime reporter. Original schema classification remains associated with the original cause. Never take a field/widget/shell back from a foreign owner to manufacture recovery.

If an exact failed field left its block but the block and healthy siblings remain owned, remove that field's authoring authority and retire its affected inline scopes. Keep the healthy owners. A later explicit descriptor replacement can retry; the foreign field is not modified or re-adopted.

If the block shell itself lost its mounted owner during the attempt or before a later query of its contained failed state, all scopes belonging to that lost block owner are affected. This remains true when the retained descriptor set is empty: an empty set does not prove a live block owner. The first stale failed-entry query retires that owner and reports the ownership failure with the original cause; subsequent queries return no fields. Retirement revokes resource scopes without removing or reparenting the adopted shell from its foreign parent. Retire the block entry and its inline state through existing teardown. The accepted canonical record remains present; this block has no authoring descriptors until a legitimate later acquisition. Other blocks remain mounted and their pending input/tasks stay valid. Do not leave a live detached block scope while merely returning an AggregateError, and do not mark the entire editor failed merely to retire A.

A later non-no-op canonical change to the missing owner may acquire it through the existing block preparation path, with recovery creation cause (`restoring: true`), valid document order and ordinary transaction settlement. Failure of that acquisition remains owned by the current canonical transaction. An explicit document replacement can likewise acquire a fresh projection through its existing path. Neither event revives predecessor scopes.

#### Canonical and mode boundaries

A presentation failure memo is not permission to commit canonical edits without projection. A legitimate native commit in healthy A.note may change document revision while the failed A.back content remains unchanged: preserve A.back's disabled state and exclude it from DOM serialization, taking that field's data/sidecars from the accepted record. The native edit alone creates its ordinary transaction/history entry.

If a canonical authoring operation actually changes the failed field's rich-text content or any referenced inline payload, bypass the settled presentation result and run current transaction preparation/projection/recovery. On failure, that current transaction rolls back; presentation recovery must not manufacture success/history or borrow an old transaction's rollback. On success, publish coherent content first and then restore only the exact host mode disabled by the failed presentation owner. A same-HTMLElement recovery must become authorable again when the editor is editable. The temporary `contenteditable` change is an attribute lease, not another field authority. Close it only when its exact installed value and owner/control identity are still intact: either on the successfully recovered current field, or on the exact retired field/unchanged prefix of its recorded original ancestor chain that ends at a genuinely detached node. Closing a retired attribute lease does not register the field, restore scopes, or reparent anything. This permits a plugin to return later to the same cached HTMLElement after an intervening successful tab. A genuinely retired attribute lease may close while the editor is read-only because it grants no live authoring authority; a live recovered host still obeys the effective committed/target mode. Thus back-failure → read-only → successful front → editable → same-back does not leave a stale host-owned false value behind. A later caller-owned attribute value, a foreign editable/widget/control reassignment, and adoption of the field or its old wrapper into a foreign container must remain untouched.

An ordinary settled query does not rewrite a failed host's attribute after the caller has replaced that attribute/control. The failed field remains absent from authoring descriptors. A mode transition captures the still-valid exact installed attribute leases before invoking the plugin hook and revalidates those same leases after the hook or rollback; only the mode-only value change of such a captured lease may be disabled again. A superseded attribute/control is not reclaimed.

A read-only round trip is not presentation retry permission. `plugin.setReadOnly(false)` must not re-enable a settled failed host. Mode propagation still updates the healthy fields and their existing scopes; failed keys remain absent and disabled until an admitted successful recovery. A legitimate mode callback may toggle `contenteditable` true/false on the same previously owned ancestor without losing the healthy field lease, provided the exact parent topology, private block owners and all other editable/widget/control boundaries are unchanged. This allowance does not admit a moved field or a new owner. Existing mode cancellation still governs pending tasks: a task cancelled by entering read-only stays cancelled, while the retained healthy occurrence may admit a fresh task after a successful return to editable mode. Canonical data, generation, revision and history remain unchanged by the mode/presentation work itself.

Forced projection during a mode change is owned by the existing read-only transition/recovery owner. Force projection does not bypass the prior exact field ownership proof: check it before field publication, after extension callbacks and at final settlement even when no field-preservation plan is used. A mode callback moving the same field into a new editable/widget owner must not make a fresh accepted lease from that new path. Legitimate mode-only changes on the same owned ancestor remain allowed. A known decoder or inline acquisition error there must request that owner's existing restoration, even when the plugin's reverse `setReadOnly` hook returns normally. Returning ready with accepted data but missing/retired inline state is not successful rollback. Successful restoration reports and rethrows the original cause with coherent current fields; restoration failure retains the existing `ReadOnlyRecoveryError`/failed-control outcome. This mode-owned path is distinct from field-local standalone refresh and does not license whole-document recovery for presentation notifications.
