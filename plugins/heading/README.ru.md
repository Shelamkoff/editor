# Блочный плагин Heading

Заголовок уровня 2–6 с выравниванием, форматированием, виджетами и выбором уровня.

## Установка и регистрация

```bash
npm install @shelamkoff/rector
```

```js
import { createEditor } from '@shelamkoff/rector'
import { createHeadingPlugin } from '@shelamkoff/rector/plugins/heading'

const editor = createEditor({
  holder: document.querySelector('#editor'),
  plugins: [createHeadingPlugin()],
})
```

Тип блока — `heading`. Фабричная функция также экспортируется общей точкой входа `@shelamkoff/rector/plugins` и может загружаться по типу документа через `@shelamkoff/rector/plugins/async`.

Эта же точка входа экспортирует `HEADING_LEVELS` — доступный только для чтения массив элементов `{ level, key, icon }` для уровней `h2`–`h6`. Поле `key` содержит локальный ключ перевода плагина, а `icon` — доверенную встроенную SVG-разметку. Массив нужен, когда элемент управления приложения должен предлагать ровно те же уровни, что и плагин; не изменяйте его элементы.

## Данные

```json
{ "text": "Раздел", "level": 2 }
```

### Поля данных

| Поле | Обязательно | Назначение и ограничения |
| --- | --- | --- |
| `text` | да | Очищенный внутристрочный HTML. Пустая строка является допустимым состоянием редактора. Поле может ссылаться на значения из карты `inline` блока. |
| `level` | да | Целое число от `2` до `6`. Новый заголовок создаётся с уровнем `2`. |

В формате документа второй версии выравнивание не принадлежит данным плагина. Оно хранится в оболочке блока как `tunes.textAlign`.

## Конфигурация

Каждый встроенный блочный плагин принимает два параметра владения стилями: `injectStyles?: boolean` по умолчанию равен `true`; укажите `false`, если приложение само включает CSS этого плагина. `css?: string` добавляет URL таблицы стилей приложения после стандартной, а при отключённой стандартной инъекции служит URL замены.


## Возможности

Внутристрочные инструменты и виджеты; вставка тегов заголовка; смена уровня; преобразование блока.

## История, жизненный цикл и стили

Экземпляр блока получает ограниченный контекст: `context.updateData(producer)` изменяет данные, `context.commitDomMutation(operation)` защищает изменения форматированного текста, а `context.beginTask()` позволяет сохранить асинхронный результат. Завершённое действие создаёт один шаг истории. Экземпляр блока и среда плагина освобождают ресурсы через `destroy()`; Rector удаляет подключённые стили после освобождения последнего владельца.

Не удаляйте контейнер редактора до вызова `editor.destroy()`.

## Вывод документа

Используйте фабричную функцию из `@shelamkoff/rector/renderer/renderers/heading`. Последовательное руководство VitePress описывает проверку данных, текущий формат документа, разработку расширений, диагностику, безопасность и стили.
