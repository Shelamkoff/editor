# Блочный плагин LinkPreview

Предварительный просмотр ссылки с семью шаблонами и необязательными метаданными приложения.

## Установка и регистрация

```bash
npm install @shelamkoff/rector
```

```js
import { createEditor } from '@shelamkoff/rector'
import { createLinkPreviewPlugin } from '@shelamkoff/rector/plugins/link-preview'

const editor = createEditor({
  holder: document.querySelector('#editor'),
  plugins: [createLinkPreviewPlugin()],
})
```

Тип блока — `linkPreview`. Фабричная функция также экспортируется общей точкой входа `@shelamkoff/rector/plugins` и может загружаться по типу документа через `@shelamkoff/rector/plugins/async`.

## Данные

```json
{
  "url": "https://example.com",
  "title": "Пример",
  "description": "",
  "image": "",
  "favicon": "",
  "domain": "example.com",
  "template": "notion"
}
```

### Поля данных

| Поле | Обязательное | Назначение и ограничения |
| --- | --- | --- |
| `url` | да | Канонический внешний адрес HTTP или HTTPS. |
| `title`, `description`, `domain` | нет | Строки метаданных; пустые значения допустимы. |
| `image`, `favicon` | нет | Пустые строки или канонические адреса, разрешённые политикой медиафайлов. |
| `template` | нет | `horizontal`, `compact`, `large-top`, `minimal`, `twitter`, `notion` или `split`; редактор и рендерер по умолчанию используют `notion`. |

`template` принимает `horizontal`, `compact`, `large-top`, `minimal`, `twitter`, `notion` или `split`. Разрешены только ссылки HTTP и HTTPS.

## Конфигурация

Каждый встроенный блочный плагин принимает два параметра владения стилями: `injectStyles?: boolean` по умолчанию равен `true`; укажите `false`, если приложение само включает CSS этого плагина. `css?: string` добавляет URL таблицы стилей приложения после стандартной, а при отключённой стандартной инъекции служит URL замены.

`fetchMeta(url, { signal })` возвращает `title`, `description`, `image`, `favicon` и `domain` и должен учитывать переданный `AbortSignal`. Адреса изображения и значка проходят общую политику адресов медиафайлов. Без этого обработчика плагин не выполняет запрос метаданных: он сохраняет очищенный URL, определяет `domain`, а остальные поля остаются пустыми, пока их не передаст приложение или загруженный документ.

Если настроен `fetchMeta`, URL фиксируется сразу, затем запускается отменяемое получение метаданных. Поздний ответ дополняет только те поля, которые приложение не изменяло после начала запроса. Если ввод URL остаётся последней операцией истории и ревизия совпадает, полученные метаданные присоединяются к ней: **один шаг отмены или повтора**. Если между вводом и ответом произошло другое изменение, метаданные образуют **отдельный** шаг истории. При ошибке URL сохраняется, а смена адреса или удаление блока отменяет устаревший запрос.


## Возможности

Вставка URL; асинхронное получение метаданных; выбор шаблона; безопасное назначение URL; освобождение ресурсов. Пока блок доступен для редактирования, нажатие карточки не открывает адрес и не уводит пользователя из редактора. В режиме отображения редактора и в готовом документе карточка работает как обычная внешняя ссылка.

## История, жизненный цикл и стили

Экземпляр блока получает ограниченный контекст: `context.updateData(producer)` изменяет данные, `context.commitDomMutation(operation)` защищает форматированный текст, а `context.beginTask()` позволяет сохранить асинхронный результат. После явного ввода URL используется `task.commit(producer, { mergeWithPreviousField: 'url' })`. Объединение с предыдущей операцией разрешено лишь при совпадении сохранённой ревизии и изменённого поля URL; промежуточные операции и прочие асинхронные результаты отменяются отдельно. Экземпляр блока и среда плагина освобождают ресурсы через `destroy()`; Rector удаляет подключённые стили после освобождения последнего владельца.

Не удаляйте контейнер редактора до вызова `editor.destroy()`.

## Вывод документа

Используйте фабричную функцию из `@shelamkoff/rector/renderer/renderers/link-preview`. Последовательное руководство VitePress описывает проверку данных, текущий формат документа, разработку расширений, диагностику, безопасность и стили.

Автоматическое дополнение метаданных не запускается повторно, когда отмена, повтор или откат неудачной команды восстанавливают снимок. Восстановленные поля URL остаются редактируемыми; явная отправка URL может запустить новый запрос. Пользовательские плагины могут учитывать флаг `context.restoring`, зафиксированный при создании блока, чтобы не повторять автоматические изменения документа при восстановлении истории.
