# Блочный плагин Checklist

Контрольный список с независимым состоянием каждого пункта.

## Установка и регистрация

```bash
npm install @shelamkoff/rector
```

```js
import { createEditor } from '@shelamkoff/rector'
import { Checklist } from '@shelamkoff/rector/plugins/checklist'

const editor = createEditor({
  holder: document.querySelector('#editor'),
  plugins: [new Checklist()],
})
```

Тип блока — `checklist`. Класс также экспортируется общей точкой входа `@shelamkoff/rector/plugins` и может загружаться по типу документа через `@shelamkoff/rector/plugins/async`.

## Данные

```json
{ "items": [{ "text": "Опубликовать", "checked": false }] }
```

### Поля данных

| Поле | Обязательно | Назначение и ограничения |
| --- | --- | --- |
| `items` | да | Непустой массив объектов. Каждый объект обязательно содержит строку `text` и логическое значение `checked`. Текст поддерживает очищенную внутристрочную разметку и виджеты. |

Проверка документа разрешает пустую строку `text`, потому что пустой пункт является допустимым состоянием редактирования. `Enter` в пустом последнем пункте удаляет его и создаёт после контрольного списка стандартный блок; `Enter` в единственном пустом пункте преобразует сам контрольный список. Каждый переход является одним отменяемым действием.

## Конфигурация

Каждый встроенный блочный плагин принимает два параметра владения стилями: `injectStyles?: boolean` по умолчанию равен `true`; укажите `false`, если приложение само включает CSS этого плагина. `css?: string` добавляет URL таблицы стилей приложения после стандартной, а при отключённой стандартной инъекции служит URL замены.


## Возможности

Внутристрочные инструменты и виджеты; добавление, удаление и переключение пункта; объединение; преобразование блока.

## История, жизненный цикл и стили

Действия плагина входят в конвейер команд через предоставленный контекст `mutate()`, поэтому одно завершённое действие создаёт один шаг отмены и повтора. Редактор подсчитывает владельцев объявленных URL стилей. Удаление блока вызывает его метод освобождения ресурсов; `editor.destroy()` освобождает оставшиеся блоки и общие ресурсы.

Не удаляйте контейнер редактора до вызова `editor.destroy()`.

## Вывод документа

Используйте фабричную функцию из `@shelamkoff/rector/renderer/renderers/checklist`. Последовательное руководство VitePress описывает проверку данных, миграции, разработку расширений, диагностику, безопасность и стили.
