# Блочный плагин List

Нумерованный или маркированный список с разделением и объединением пунктов, выходом из списка и преобразованием выбранной части.

## Установка и регистрация

```bash
npm install @shelamkoff/rector
```

```js
import { createEditor } from '@shelamkoff/rector'
import { createListPlugin } from '@shelamkoff/rector/plugins/list'

const editor = createEditor({
  holder: document.querySelector('#editor'),
  plugins: [createListPlugin()],
})
```

Тип блока — `list`. Фабричная функция также экспортируется общей точкой входа `@shelamkoff/rector/plugins` и может загружаться по типу документа через `@shelamkoff/rector/plugins/async`.

## Данные

```json
{
  "style": "unordered",
  "items": [
    {
      "id": "item-1",
      "text": "Первый пункт"
    },
    {
      "id": "item-2",
      "text": "Второй пункт"
    }
  ]
}
```

### Поля данных

| Поле | Обязательно | Назначение и ограничения |
| --- | --- | --- |
| `style` | да | `ordered` или `unordered`. Новый список использует вариант, выбранный пользователем в меню добавления. |
| `items` | да | Непустой массив строк, в котором хотя бы один пункт не пуст. Каждая строка содержит очищенный внутристрочный HTML и может ссылаться на карту `inline` блока. |

Пустой последний пункт — временное состояние редактирования, а не допустимые сохранённые данные списка. `Enter` в таком пункте удаляет его и создаёт после списка стандартный блок редактора как одно отменяемое действие. `Enter` в единственном пустом пункте преобразует сам список в стандартный блок.

В непустом пункте `Enter` разделяет содержимое в позиции каретки: часть до каретки остаётся в текущем пункте, а часть после неё переходит в новый следующий пункт. Если есть выделение, редактор сначала удаляет выбранный фрагмент; невыбранный остаток после выделения становится новым пунктом. Это правило действует и для выделения через несколько пунктов. `Backspace` в начале любого пункта, кроме первого, объединяет его с предыдущим. Каждое такое структурное изменение создаёт один шаг истории.

При преобразовании части списка выбранные пункты удаляются из исходного списка, нумерация обновляется, а новый блок вставляется сразу после списка. Текстовый блок получает выбранную внутристрочную разметку; нетекстовый блок создаётся со своими начальными данными.

## Конфигурация

Каждый встроенный блочный плагин принимает два параметра владения стилями: `injectStyles?: boolean` по умолчанию равен `true`; укажите `false`, если приложение само включает CSS этого плагина. `css?: string` добавляет URL таблицы стилей приложения после стандартной, а при отключённой стандартной инъекции служит URL замены.


## Возможности

Внутристрочные инструменты и виджеты; два варианта в меню добавления; вставка списка из буфера; разделение по `Enter`; объединение по `Backspace`; преобразование всего блока или выбранной части.

## История, жизненный цикл и стили

Экземпляр блока получает ограниченный контекст: `context.updateData(producer)` изменяет данные, `context.commitDomMutation(operation)` защищает изменения форматированного текста, а `context.beginTask()` позволяет сохранить асинхронный результат. Завершённое действие создаёт один шаг истории. Экземпляр блока и среда плагина освобождают ресурсы через `destroy()`; Rector удаляет подключённые стили после освобождения последнего владельца.

Не удаляйте контейнер редактора до вызова `editor.destroy()`.

## Вывод документа

Используйте фабричную функцию из `@shelamkoff/rector/renderer/renderers/list`. Последовательное руководство VitePress описывает проверку данных, текущий формат документа, разработку расширений, диагностику, безопасность и стили.
