## Подтверждённые находки

### POLL-R1 — неизменённый initialResults откатывал свежие результаты (P2)

Начальный snapshot: revision `1`, голоса 20/80, выбран `b`. Backend загружает revision `2`, голоса 70/30, выбран `a`. Обычная правка вопроса/подписи либо настройки возвращала показ к 20/80 и выбору `b`. Затем устаревшая subscription revision `1.5` ошибочно принималась, поскольку текущая revision тоже откатилась.

`update(next)` выбирал `data.initialResults ?? runtime`, хотя persisted seed не изменялся. Теперь неизменённый seed не заменяет подтверждённый runtime. Явное изменение или удаление initialResults сохраняет свои прежние авторские/history semantics. Исправлено в `f1ba88f`.

### POLL-R2 — смена pollId наследовала ревизию и afterVote старого опроса (P2)

Без seed после переключения `poll-1` → `poll-2` новая revision `1` отклонялась на фоне revision `20` предыдущего опроса. Отдельный тест с возрастающей revision доказал независимую ошибку видимости: `afterVote` продолжал показывать результаты нового опроса, хотя для него не было голоса.

Смена pollId теперь начинает независимое состояние результатов/голосования из нового seed либо пустого snapshot. Старое соединение освобождается, его callback не может изменить новый опрос. Исправлено в `f1ba88f`.

### POLL-R3 — разные массивы option IDs совпадали после join('|') (P2)

Схема допускает непустые строковые ID. Массивы `['a|b', 'c']` и `['a', 'b|c']` оба превращались в `a|b|c`. Замена вариантов не обновляла подписку и не запускала новую загрузку.

Идентичность набора теперь проверяется длиной и поэлементным сравнением ID. Ограничения формата пользовательских ID не добавлялись. Исправлено в `f1ba88f`.

### POLL-R4 — сохранённый native input откатывался в DOM при read-only (P1)

Настоящий NativeInputController сохраняет обычный ввод с `preserveSourceProjection`. DocumentRuntime передаёт `sourceBlockId`, а BlockReconciler намеренно не вызывает `instance.update()` для этого источника, чтобы сохранить native DOM. У Poll оставалась устаревшая авторская копия `data`.

После набора `Physical text` модель и DOM первоначально содержали этот текст. Переключение read-only туда/обратно восстанавливало в DOM прежние `Question` / `A`, хотя модель всё ещё содержала введённый текст. Обновления голосов также рисовали старую подпись варианта.

Poll теперь получает авторские данные через существующий канонический `context.getData()` перед runtime-only и read-only проекцией. Подтверждённые результаты голосования при этом не сбрасываются; runtime-only обновление сохраняет существующий редактируемый DOM-узел. Исправлено в `2ebf060`.

## Доказательства и воспроизводимость

- **39/39 Node tests**, 0 failures, 0 skipped. Это выбранный поднабор, не полный `npm test` репозитория.
- Первые 11 новых browser cases: baseline 8 FAIL / 3 PASS; после первого исправления 11 PASS.
- Три новых native-source cases: на коде первого исправления 3 FAIL; после второго исправления 3 PASS.
- Итоговые 14 cases на исходном HEAD: **11 FAIL / 3 PASS**; на финальном коде: **14 PASS**, без browser errors.
- Реальный Chromium input для question и option: `isTrusted: true`, каноническая модель сначала содержит введённый текст; до native-фикса mode round trip возвращает старый DOM, после — сохраняет введённый текст в обоих случаях. Это два независимых сценария, каждый выполнен до/после исправления.
- Все 32 доступных JavaScript-файла локального поднабора прошли `node --check` без удаления ESM imports. Это синтаксическая проверка, а не TypeScript gate.

Среда: Node.js 22.16.0, Chromium 144.0.7559.96. В браузере исполнялись настоящие Poll, схемы, sanitizer, NativeInputController и ядро истории/транзакций. Backend ответами и внешним runtime/projection adapter управлял тест. Адаптер воспроизводит проверенный по исходникам контракт `sourceBlockId` и candidate-read; полный createEditor/BlockReconciler в этих probes не исполнялся. В зарегистрированных native-source cases input синтезируется, отдельно выполненный физический probe использует настоящий ввод Chromium.

Офлайн-загрузчик менял только адреса ESM imports и базу `import.meta.url` на Blob-модули. Не заменялись методы production-модулей, schema или sanitizer. Сетевые зависимости/полный checkout недоступны, поэтому запуск Vite runner на всём проекте не заявляется. Набор зарегистрирован отдельной страницей `tests/browser/poll-state-contracts.html` в существующем `tests/browser/run.mjs`.

## Паритет и отрицательные контроли

В v1 прочитан Poll: `#syncFromDom` обновляет авторский текст, не заменяя живые результаты persisted seed. Это исходное подтверждение разделения состояний, **не новый полный differential browser run v1/v2**. Для всей библиотеки остаётся обязательной проверка поведения, а не только совпадения реестров типов.

Локальное голосование, явная замена/удаление initialResults и освобождение подписки уже проходили на baseline. Они оставлены как положительные контроли, а не объявлены новыми дефектами. Локальный голос по-прежнему создаёт одну history operation и корректно отменяется/повторяется; backend vote не записывается в авторскую историю. Несовместимые старые API/JSON не возвращались ради паритета. Прежняя переклассификация Tooltip как ложного срабатывания сохраняется; новых обвинений в дефекте Window timers нет.

## Не выполненная общая приёмка

На этом HEAD не выполнены полные typecheck 5.9.3, npm test, все browser/native suites, реальный системный IME, Firefox/WebKit, полный heap/retention stress, package consumers, docs build и полная матрица поведения всех блоков/инструментов. Полный AST-граф проекта также не перестраивался: прочитан его существующий аудит, но исходники всего checkout не были доступны локально.

На полном checkout новый набор запускается через зарегистрированный browser runner:

```sh
EDITOR_BROWSER_PAGE=poll-state-contracts.html node tests/browser/run.mjs
```

Полная приёмка остаётся отдельным последовательным прогоном проектных команд на окончательном SHA. Найденные четыре проблемы исправлены; отсутствие остальных подтверждённых находок в этом проходе не является сертификацией всей библиотеки.
