The cross-cutting P00–P14/I01–I10 conditions were reviewed with those boundaries:
canonical acceptance has one owner; admission precedes user code and is
revalidated; public mutable snapshots do not alias immutable model/history/events;
exact occurrence identity outlives neither cancellation nor disposal; nested
commands see the active draft; known-schema failures do not become opaque data;
failure presence does not depend on a truthy thrown value; observer/view failure
cannot undo an accepted commit. Literal records include own dictionary keys,
stable item/field IDs, direction, marks, widgets, versions and unknown sidecars.
Invalid private wire is rejected before fallback; source cancellation is
selective rather than a global revision kill switch. No new store, global
authority manager, generic media engine, legacy decoder or removed API alias
appears in the final implementation.

Superior current behavior stays: strict admission and URL policy, working
foreign/Trusted Types media fallbacks, exact cleanup, richer canonical data,
fixed Gallery narrow layouts and safer confined HTML. Raw historical defects
and unavailable legacy APIs are not treated as desired behavior or successful
candidate bodies.
