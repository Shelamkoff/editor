# Continuation history and deferred callbacks — proof in progress

The new public fixture has 22 cases and 230 independently reconstructed
expectations. It targets only `CONTRACT_BLOCK_INLINE_CONTINUATION`,
`CONTRACT_ASYNC_OBSERVER_ADMISSION` and `CONTRACT_DEFERRED_DIAGNOSTIC`.
The register remains 82 accepted / 127 open until committed-source validation.

Block and inline URL/title completion use their actual public contexts.
Eligible block history groups; inline work remains independently undoable.
Host-origin, intervening-action, changed-field, wrong-field and query/no-op
controls preserve exact data, live labels, command origins and Undo/Redo.
The unsupported host inline patch is explicitly rejected before exercising a
still-live inline task through its supported context. It is not a new API.

Publication rejects synchronous reentry before the nested producer, then a
controlled await permits a separate command on a live public handle. Mode
changes and destruction do not revive old tasks, getters or producers; a
successor editor retains independent authority. Diagnostic error-name capture
is guarded and content-free; queued application delivery can issue a later
independent command. Error and falsy late Promise rejections preserve accepted
data and history without an unhandled rejection or retrospective rollback.

The exploratory candidate passes 22/22 cases and 230/230 manual expectations;
the specification baseline retains 17 passing and five failed/incomplete cases
with 206 observations. Earlier probes used a wrong transaction name and an
unsupported host inline patch/nested context call. Those are preserved fixture
diagnostics, not product RED evidence or reasons to broaden the public port.

Production modules are exact Git objects for v1, specification baseline and
candidate. The committed public fixture and original harness are shared by
both v2 sources. A test-only descriptor wrapper awaits each case and records
observations without executing result getters. The full ordinary browser run
contains all 46 pages, including this new final page, without that wrapper.
`review.py` imports neither fixture nor production code. It manually rebuilds
all canonical/history/callback expectations, verifies source/dependency bytes,
requires ordinary execution and binds unchanged runtime to separately
integrated `f2070510` through its original 21-gate manifest.

v1's diagnostic capability is executed explicitly. Its native `save.slow`
callback runs synchronously; a controlled Promise continuation then uses its
real public `render` method and produces the expected saved and visible text.
The current queued callback policy and scoped task API are not emulated in v1.
Its six private plugin task references remain recorded. No native gesture or
full-library acceptance is claimed, and no production behavior changes.
