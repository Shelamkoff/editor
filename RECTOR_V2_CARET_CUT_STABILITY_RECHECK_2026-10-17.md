## Результат

Подтверждены три практических дефекта. Исправлены в текущих владельцах операций без новых менеджеров, архитектурных слоёв или legacy-путей. Проверены целевые регрессии и независимые контрольные сценарии. **Это не подтверждение полной стабильности всей библиотеки.**

### D1: List перемещал неизменённый редактируемый LI (P2)

`plugins/list/index.js` в каждом `reconcile()` выполнял `list.appendChild(li)`, в том числе для неизменённых элементов и неизменённого порядка. В настоящем Chromium перенос подключённого `contenteditable` элемента теряет native caret/focus. Изменение текста **другого** элемента списков поэтому могло сбросить фокус.

Исправление: точечная вставка `insertBefore` только если фактическая позиция `li` не соответствует authored order. При неизменённом порядке DOM-узел остаётся подключённым.

- [Код / green](https://github.com/Shelamkoff/editor/commit/c724b6ade87627e3e35fd10c87541182aca4652a): **3/3** успешных теста.
- [Детерминированная проверка порядка](https://github.com/Shelamkoff/editor/commit/0f805d69251a1676a5b81f99c8d2ae4a8ddeb9f1): ещё один тест с 600 независимыми операциями вставки/удаления/перестановки/no-op. На финальном исходнике **4/4 PASS**.

### D2: Table переподключал неизменённые строки и ячейки (P2)

`plugins/table/index.js` безусловно выполнял `table.appendChild(row)` и `row.appendChild(cell)`. При обновлении соседних ячеек это переносило текущий `TD/TH` и могло сбросить каретку. Предшествующий исправленный контракт позиционных заголовков сохраняется: `ensureCellTag` заменяет узел только при изменении требуемого `TH/TD`.

Исправление: для строк и ячеек используется индексная проверка непосредственных детей перед `insertBefore`.

- [Код / green](https://github.com/Shelamkoff/editor/commit/14064c721f19627d733d9b29c3dfb701576133d9): **4/4 PASS**.
- [Property tests](https://github.com/Shelamkoff/editor/commit/e0d77eddb54eb2767f63ed2c973f89362d30a083): +600 операций с независимым массивом ID / ожидаемыми positional `TH/TD`; текущая матрица **5/5 PASS**. Дополнительно 3/3 старых теста HTML Table import.

### D3: Ошибка подготовки Cut допускала native deletion (P1)

В `core/ClipboardController.js` после подтверждения owned selection вызов `runtime.prepareLogicalClipboardSlice()` происходил до `event.preventDefault()`. Ошибка синхронной подготовки позволяла браузеру выполнить стандартный Cut, удалив выбранный DOM-текст без канонического коммита и истории.

Изолированный реальный Chromium/CDP контроль: физический `Ctrl+X` по выделению `cd` в `abcdef` при исключении из обработчика **до** `preventDefault` оставляет `abef`. Тот же сценарий при отмене события **до** исключения оставляет `abcdef`. Это браузерное свойство, а не подмена обработчика упрощённой моделью.

Исправление: после проверки принадлежности контроллер отменяет браузерное Cut **до** fallible selection/slice/preparation. Дальнейшие исключения подготовки локально подавляются и передаются в существующий diagnostic `cut.failed`. Для `plain-text` полей нативное Cut оставлено как прежде; редактор не перехватывает его.

## Браузерные регрессии

Изменённые сценарии зарегистрированы в существующей инфраструктуре:
- `tests/browser/native-plugin-parity.js`: List/Table — публичный `blocks.update()` соседнего поля, сохранение фокуса, caret, дальнейший native input и Undo;
- `tests/browser/native-clipboard.js`: нативный `Ctrl+X` с намеренно падающей clipboard capability не изменяет документ или текст;
- исходные ранее зарегистрированные Table и HTML import сценарии сохранены.

**Регистрация тестов и синтаксический разбор не равны прохождению браузерного gate.** На финальном полном checkout эти новые сценарии ещё требуется выполнить.

## Проверенные независимые факты / отсев ложных тревог

- Chromium на отдельном DOM-контроле подтверждает, что безусловные `appendChild` для уже установленных editing hosts перемещают каретку на контейнер; условные `insertBefore`, не затрагивающие неизменённые узлы, сохраняют text-anchor и offset.
- При отсутствии ownership для `plain-text` поле сохраняет стандартный Cut; дополнительный отрицательный тест это фиксирует. Запрет всего Cut на всём root был бы неверным и **не применялся**.
- Ранее внесённый Table `TH/TD` positional fix повторно прошёл 5 тестов общего reconciliation-поднабора; перекрывать его полным пересозданием DOM не потребовалось.
- `InlineProjectionRuntime.js` и `EditorRenderer` рассмотрены отдельно на предмет аналогичного шаблона, но **нового подтверждённого дефекта в них этим проходом не установлено**; отсутствие находки не является полным покрытием.

## Фактический масштаб проверки

Целевые тесты исполняли production-исходники List/Table/ClipboardController с контролируемыми DOM/runtime-adapters в изолированной V8-среде. Они проверяют публично наблюдаемые порядки/хосты/отмену event, но **не являются полным Node ESM/npm run**. В Chromium непосредственно исполнялся браузерный DOM/Cut-контроль до/после с реальным native input через CDP; это не полный `createEditor`.

Дополнительно локально повторён ранее материализованный базовый ESM-набор модели/истории/индекса: **39/39 Node PASS**. Он не представляет собой checkout нового Git HEAD, и к нему нельзя приписывать новые Table/Clipboard исправления.

Из исходников новых browser suites и изменённых production файлов выполнен синтаксический разбор после нейтрализации import/export в изолированном VM. Полные `npm ci`, `npm test`, TypeScript 5.9.3, Vite native browser matrices, installed tarball, реальный OS IME, Firefox/WebKit и memory stress **не выполнены на новом HEAD**. GitHub CI недоступен; полные проверки должны быть воспроизведены локально после синхронизации.

## Вывод

Три воспроизведённых дефекта закрыты и снабжены TDD-регрессиями. Прежние фиксы паритета Table/Poll/Undo сохраняются в ветке.
