Состояние: **две подтверждённые проблемы Table устранены**. Полная стабильность редактора не утверждается.

## T1. Заголовочная строка зависела от старой идентичности первой строки (P2)

**Контракт:** при `withHeadings=true` HTML-ячеек `<th>` должна быть первой строка *в актуальном порядке*, а остальные строки содержат `<td>`. Перестановка, вставка и удаление авторских строк допускаются через публичный `blocks.update()` с сохранением идентификаторов.

**Сбой:** `plugins/table/index.js` вызывал `ensureCellTag()` исключительно при изменении самого флага `withHeadings`. При перестановке `['a','b'] → ['b','a']` в DOM оставались `a:TH` и `b:TD`, хотя `b` уже была первой. После удаления `a` строка `b` оставалась `TD`. В v1 теги определяются по индексу в каждом `render()`.

**Решение:** `reconcile()` всегда проверяет соответствие фактического тега позиции; `ensureCellTag()` заменяет узел лишь при несовпадении. Нет бессмысленной замены неизменённых ячеек и нет изменения публичного data API.

**Коммиты:** [регрессионные тесты](https://github.com/Shelamkoff/editor/commit/931a89de2cb07a71f2be941b3934d55705b9d558), [исправление](https://github.com/Shelamkoff/editor/commit/f46695c4f5cb680423c115680cc2f69c814b0102).

**Доказательство red/green:** три новые Node-регрессии на **фактическом тексте production Table definition** выполнены в изолированной V8-среде с минимальным DOM-адаптером:
- до исправления **0/3 PASS** (все три падают на несоответствии `TH/TD`);
- после исправления **3/3 PASS**;
- покрыты reorder, remove-first, insert-first, обычная сортировка без headings и переключение флага.

Тесты зарегистрированы в `plugins/table/table-reconciliation.test.js`; вместе с исправлением выполнено также статическое сравнение исходного Table v1. Полный `node --test` именно с этим новым файлом на checkout не выполнен.

## T2. Пустая первая HTML-строка скрывала заголовки при Paste (P2)

**Контракт v1:** при импорте таблицы проверяется *первая строка с ячейками*, а не первый HTML `<tr>`.

**Сбой v2:** `htmlImport.importRoot()` отбрасывал строки без прямых ячеек при построении canonical `rows`, но вычислял `withHeadings` по исходному `rowElements[0]`. В примере `<table><tr></tr><tr><th>Name</th></tr><tr><td>A</td></tr></table>` получался `withHeadings=false`, тогда как v1 получает `true`.

**Решение:** распознавать headings по первой строке с собственными прямыми `TH/TD`. Сохранён строгий current schema: одинаковая ненулевая ширина строк, стабильные IDs и структурная таблица вместо рыхлого HTML.

**Коммиты:** [тесты](https://github.com/Shelamkoff/editor/commit/27936361af259c2e4a9a25b7d5f2b5c1d3be11bb), [исправление](https://github.com/Shelamkoff/editor/commit/0992d9cd4b7db34c18b7c5f152ad64941c541df3).

**Доказательство red/green:** три capability-теста реального `createTablePlugin()` на DOM-образных input values:
- до исправления **2/3 PASS**, именно первый пустой `tr` даёт FAIL;
- после исправления **3/3 PASS**.

Тесты сохранены в `plugins/table/table-import.test.js`.

## Отсеянные подозрения

- **Tab на границе Table.** В v1 `#navigateCell()` возвращает `false`, если соседней ячейки нет: событие остаётся браузеру. В v2 capability возвращает `null` на той же границе. Это не новая потеря функциональности; код не менялся.
- **Коллизия rowId/cellId.** `tableFieldKey()` уже экранирует `%` и `:`; существующая `native-plugin-parity` матрица проверяет разделение конфликтующих ID. Новая архитектура ID не требуется.
- **Стабильные неизменённые узлы ячеек.** После фикса `ensureCellTag()` сохраняет текущий элемент, если его `tagName` соответствует позиции. Принудительная полная перерисовка была бы ложной «защитой», уничтожающей состояние каретки.

## Другие проверки и ограничения

Повторно выполнен доступный локальный **изолированный набор из 39 Node-тестов модели/истории/индекса: 39/39 PASS**. Это исходники ранее материального поднабора, а не новый запуск полного проекта после Table-коммитов. В этом проходе также проверены состав актуальной ветки и недавние изменения HTML/Poll; весь `git clone` заблокирован отсутствием DNS до GitHub в контейнере.

Для окончательной приёмки нужны проектные `npm ci`, `npm run typecheck`, `npm test`, `npm run test:browser`, package/docs/type gates, настоящий native IME, Firefox/WebKit, memory/heap и full v1/v2 behavioral differential. Непроверенные области не считаются ни ошибочными, ни доказанно стабильными.

**Вывод:** два фактически подтверждённых расхождения Table устранены. По этому проходу нет оснований объявлять всю библиотеку стабильной, но также нет оснований объявлять дефектами перечисленные отсеянные подозрения.
