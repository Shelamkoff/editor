# Внутристрочные инструменты и плагины

В Rector существуют две разные inline-модели: инструменты форматирования изменяют выбранный rich-text диапазон, а definitions внутристрочных плагинов сохраняют структурированные виджеты в канонической карте `inline` блока.

## Контракт inline tool

```ts
interface InlineTool {
  readonly type: string
  readonly title?: string
  readonly icon: string
  readonly shortcut?: string
  readonly tag?: string
  bindSelectionPort?(port: InlineSelectionPort | null): void
  isActive(selection: InlineSelection): boolean
  toggle(selection: InlineSelection): void
  renderActions?(context: InlineToolActionContext): HTMLElement | null
  getIcon?(active: boolean): string
  getTitle?(active: boolean): string
  onMount?(button: HTMLElement, mutations?: InlineMutationContext): void
  isDropdownOpen?(): boolean
  destroy?(): void
}
```

`InlineSelection.textAlign` описывает текущее каноническое выравнивание выбранных блоков с разрешённым форматированием: `left`, `center`, `right`, `justify` или `mixed`. Инструмент может читать его для обновления иконки, названия и активного состояния без открытия панели действий.

`InlineToolActionContext` содержит `range`, `mutate(operation)`, `getTextAlign()`, `setTextAlign(value)`, `restoreSelection()`, `close()`, `showTooltip(anchor, label, shortcut?)`, `hideTooltip()` и необязательный локализованный `backLabel`. Закрытие панели восстанавливает сохранённое выделение документа. Новое выделение документа, закрытие панели, замена документа или любого выбранного экземпляра блока, read-only, уничтожение либо ошибка фабрики отзывают контекст. Сохранённые callbacks не могут вызвать функцию изменения, прочитать выравнивание нового владельца, восстановить выделение, закрыть следующую панель или показать её подсказки.

При открытии панели тулбар фокусирует первое доступное поле или кнопку, если панель ещё не владеет фокусом. `Escape` из любого элемента закрывает панель и возвращает сохранённое выделение документа; элемент может забрать `Escape` через `preventDefault()` или `stopPropagation()`. Отозванная панель не может восстановить фокус или закрыть следующую панель.

При подключении инструмента ядро вызывает `bindSelectionPort(port)`, а при уничтожении — `bindSelectionPort(null)`. `InlineSelectionPort.range` возвращает свежий вид текущего авторского диапазона, а не длительное право на изменение. `capture(range?)` выдаёт непрозрачный `InlineSelectionBookmark`, только если переданные границы соответствуют текущим зарегистрированным экземплярам полей и логическим позициям. Эквивалентные границы текстового узла и его родителя допустимы; совпадающий текст в другом интервале или поле — нет. Каждому редактору нужны собственные изменяемые экземпляры инструментов.

`InlineMutationContext` предоставляет `mutate(bookmark, operation)` для смонтированных элементов управления. Непрозрачный дескриптор нужно получить через контекст выделения этого инструмента; обычный `Range` не даёт права на изменение. Необязательный `restoreSelection(bookmark)` восстанавливает то же актуальное выделение без изменения данных или истории и возвращает `false` для чужого, заменённого или отозванного владельца. `port.restore(bookmark, { endOffsetDelta })` корректирует исходный конец диапазона в порядке DOM и единицах `UTF-16` только внутри собственного действия форматирования; смещение не накапливается, исходное направление сохраняется. Панель действий использует собственные `InlineToolActionContext.range`, `mutate(operation)` и `restoreSelection()` на всём протяжении действия, а не дескриптор основной кнопки.

Инструмент форматирования не хранит отдельные данные. Выделение может охватывать несколько зарегистрированных полей форматированного текста одного или нескольких блоков; инструмент доступен только при разрешении каждого затронутого блока. Изменение DOM проходит одной защищённой транзакцией и нормализуется во все затронутые блоки. Поля `plain-text` и вспомогательные поля ввода не форматируются частично. `setTextAlign()` изменяет только `tunes.textAlign` выбранных блоков, не записывая CSS или `data.align` в данные плагина.

Встроенный набор предоставляет `bold`, `italic`, `strikethrough`, `link`, `code`, `marker`, `bgcolor`, `fontSize`, `script`, `align`, `caseTransform` и `clearFormatting`.

## Definition inline plugin

```ts
interface InlinePluginDefinition<Data> {
  readonly type: string
  readonly label: { key: string, fallback: string }
  readonly icon: string
  readonly styles?: readonly string[]
  readonly trigger?: string
  readonly schema: InlineWidgetSchema<Data>
  toText?(data: Readonly<Data>): string
  readonly paste?: InlineWidgetPasteCapability<Data>
  readonly editing?: InlineWidgetEditCapability<Data>
  readonly insertion?: { createInitial(): InlineFreshInsertion<Data> }
  setup(context: InlinePluginRuntimeContext): InlinePluginRuntime<Data>
}
```

ID виджета принадлежит модели документа. Rich text хранит ссылку `{{id}}`, а `inline[id]` блока — type, версию данных и данные. DOM-проекция каждый раз строится из этой канонической пары.

Если inline-расширение не установлено, каноническая ссылка `{{id}}` и непрозрачные данные в карте данных виджетов сохраняются. Редактор показывает те же символы в инертном нередактируемом DOM-маркере, занимающем одну логическую позицию курсора; отсутствующее расширение при этом не запускается, а ссылка не превращается в буквальный текст. Без соответствующей записи в карте `inline` `{{id}}` остаётся обычным редактируемым текстом. Эти DOM-маркеры — внутренний механизм владения, а не новый сохраняемый HTML-тег или API плагинов.

Пользователь может набрать буквальные символы `{{id}}`, даже если этот ID уже принадлежит виджету. Rector сохраняет **обычный текст**, не создавая вторую ссылку, как `<span class="oe-inline-literal">{{id}}</span>` в каноническом rich-text HTML. Класс — зарезервированный внутренний маркер сериализации, а не API расширений и не визуальный стиль. Санитизация, координаты выделения, переназначение ID и рендер сохраняют буквальный текст; ссылкой на виджет считается только немаркированный принадлежащий блоку токен. Расширения не должны добавлять или удалять маркер для подмены виджета.

В составных блоках каноническая inline-ссылка может находиться в скрытом rich-text поле без смонтированного DOM. Rector защищает совпадающий текст пользователя в *других* видимых полях, не переписывая настоящую ссылку скрытого поля и её непрозрачный payload. Запись в карте данных виджетов **без** канонической ссылки не даёт права восстановить виджет из случайно совпавшего набранного текста: такой ID также защищается как буквальный, пока каноническая сборка не удалит неиспользуемую запись. Порядок сериализации полей на эти правила не влияет.

### Канонический текст без экземпляра виджета

Необязательный чистый синхронный `toText(data)` предоставляет обычный канонический текст виджета для вспомогательных подписей блока. Например, определение значка может содержать:

```js
toText(data) {
  return data.label
}
```

Редактор захватывает метод один раз вместе с исходным получателем `this`. Аргумент — отдельный снимок, декодированный захваченной схемой и неизменяемый на всех уровнях вложенности. Верните строку синхронно; промисы, вызываемые промисоподобные объекты, результаты другого типа и выброшенные значения отклоняют операцию через её существующий путь восстановления. Обработчик не получает контекст выполнения или DOM и не должен создавать виджеты, обращаться к источникам данных, менять документ или создавать задачи.

Экземпляры блоков запрашивают этот текст через [`context.getFieldText(fieldKey)`](/ru/guide/extensions#канонический-текст-несмонтированного-поля). Общий разборщик обрабатывает настоящие ссылки, буквальные токены и сущности; блок не декодирует данные конкретного типа виджета. Возвращённая строка является обычным текстом и не разбирается повторно. Неизвестное определение или определение без `toText` сохраняет символы своего канонического токена в производном тексте. Mention включает настроенный символ запуска и имя, Color возвращает каноническое значение цвета. Настоящее смонтированное представление, включая временные подписи и различия режимов, по-прежнему принадлежит проекции виджета и `afterProjection`.

## Runtime и экземпляр виджета

Ядро устанавливает и поддерживает `data-inline-plugin` и `data-id` на стабильном корневом элементе экземпляра. Расширению не нужно записывать эти атрибуты. Они обеспечивают атомарные координаты: виджет занимает одну позицию родительского поля независимо от длины подписи. Сериализацией управляет закрытая привязка экземпляра; копирование DOM-атрибутов не создаёт виджет или payload. Содержимое и редактируемое/read-only представление остаются ответственностью виджета.

После полной нормализации схемы каноническая сборка подсчитывает принадлежащие блоку ссылки в текстовых узлах всех rich-text полей, включая скрытые. Дублирующиеся ссылки отклоняют изменение. Токены в атрибутах и литеральные токены без собственного payload не учитываются. Данные незагруженных расширений сохраняются, пока на них есть ссылка; при смысловых изменениях удаляются только неиспользуемые записи.

`InlinePluginRuntimeContext` предоставляет `ownerDocument`, `signal`, `t(key, fallback, params?)` и `showPopup(anchor, content, cleanup?)`. Параметры перевода подставляются вместо шаблонов вроде `{level}` через общий словарь редактора. `showPopup()` возвращает замороженный `{ close(): void }` для одной презентации. Сохраняйте исходный дескриптор в обработчиках: устаревший дескриптор не закрывает новый popup или popup другого расширения. Ядро закрывает popup при внешнем клике, удалении якоря, переходе read-only и уничтожении.

Якорь и содержимое должны быть HTML-элементами документа владельца; переданная очистка должна быть функцией. Содержимое popup должно быть отсоединённым от документа элементом, а не уже смонтированным узлом другого приложения или корня редактора (включая якорь): Rector отклоняет такой запрос, чтобы не переносить редактируемые элементы во временное окно. Некорректные аргументы отклоняются до замены popup. Недоступный якорь или режим взаимодействия возвращает уже закрытый дескриптор с однократной попыткой очистки. Очистка вызывается после отзыва презентации под наблюдательными полномочиями: изменять документ, управление и задачи нельзя. Ошибки и асинхронное завершение изолируются. Новый popup, открытый из очистки, сохраняет приоритет перед устаревшим внешним запросом.

`InlinePluginRuntime` предоставляет `create(id, initial, context)`, необязательные `onTriggerQuery(session)`, `onTriggerKeydown(event, session)`, `onTriggerCancel()` и `destroy()`.

Каждый `create()` возвращает `InlineWidgetInstance` с `element`, необязательным `update(next, previous)`, `setReadOnly(readOnly)`, необязательным `focus()` и `destroy()`. Поле `element` должно быть новым отсоединённым `HTMLElement` из `ownerDocument` редактора. Корневой элемент принадлежит одному живому экземпляру до завершения очистки. Уже подключённые, имеющие родителя, созданные в чужом документе или принадлежащие другому экземпляру элементы отклоняются. Отклонённый повторный захват не вызывает `destroy()` исходного владельца. Если definition поддерживает нативное удаление внутри виджета через `editing.reconcileNative`, синхронный `update(next, previous)` **обязателен**. Дополнительно экземпляр может реализовать синхронный `afterNativeEdit(notice)` для временного UI/поиска; это наблюдательное уведомление, а не команда.

`InlineWidgetContext` предоставляет ровно `id`, `blockId`, `fieldKey`, `signal`, `getData()`, `updateData(producer)`, `commitDomMutation(operation)`, `beginTask()` и `isReadOnly()`. Выделением inline ID управляет ядро.

`commitDomMutation()` синхронно меняет принадлежащее виджету зарегистрированное rich-text поле/вхождение, после чего ядро сериализует полный блок в существующую транзакцию. Каноническое изменение создаёт один шаг отмены; равный результат не создаёт истории. Ошибка, возвращённый `Promise` либо промисоподобный объект или исключение свойства `then` восстанавливает сохранённую проекцию и выделение; неудачное восстановление сохраняет поведение состояния отказа. Отозванный/read-only/неисправный контекст не вызывает обработчик, а подготовленный контекст или защищённый повторный вход отклоняются до вызова. Данные меняйте через `updateData()`, асинхронную работу выполняйте через `beginTask()`. Не планируйте отложенные DOM-изменения из защищённого обработчика.

## Trigger-сессии

Definition может объявить `trigger` длиной в один Unicode code point. Ядро владеет диапазоном trigger и передаёт runtime временный `InlineTriggerSession`. Поиск и pagination — временный UI; только `session.commit(data)` создаёт каноническую вставку.

Сессия отзывается при смене фокуса, замене документа, read-only переходе, уничтожении или появлении новой сессии. Сохранённые callbacks старого UI должны становиться инертными.

## Paste и программная вставка

`paste.patterns` задаёт текстовые patterns; `fromMatch(match)` возвращает канонические данные виджета либо `null`.

`insertion.createInitial()` используется `editor.insertInlinePlugin(type, data?)` и возвращает payload виджета либо обычный текст.

`editing.handle(input, data)` обрабатывает model-first редактирование сохранённого виджета и возвращает `null` для пропуска либо синхронное действие `update`, `remove` или `replace-text`. Действие может включать необязательное неотрицательное `caret` — локальную позицию в единицах `UTF-16` внутри подписи, а не право на изменение браузерного `Range`. Ввод и результат подготавливаются под защитой runtime; ошибка уже принадлежащего редактору действия не передаётся нативному fallback.

Необязательный `editing.reconcileNative({ inputType, beforeText, text }, data)` разрешает нативное согласование удаления подписи: `deleteContentBackward/Forward`, `deleteWordBackward/Forward` и `deleteSoftLineBackward/Forward`. Метод обязан быть чистым и синхронным и **возвращать действие**, а не `null`. Редактор хранит одно ожидающее событие ввода, захватывает вхождения текущего rich-text поля и согласует соседний текст, inline-payload и живой экземпляр одной атомарной транзакцией. Удалённые подписи теряют идентификатор, сохранённые экземпляры получают окончательно нормализованные данные через `update()`. `afterNativeEdit({ inputType, text, labelChanged, caret })` — уведомление после завершения, где `caret` — локальное смещение в единицах `UTF-16` внутри подписи либо `null`. Отсутствующий/некорректный диапазон не позволяет угадывать границы слова или изменять другое поле.

## Пример регистрации

```js
import { createColorSwatchPlugin } from '@shelamkoff/rector/inline-plugins/color'
import { createMentionPlugin } from '@shelamkoff/rector/inline-plugins/mention'

const editor = createEditor({
  holder,
  plugins,
  inlinePlugins: [
    createColorSwatchPlugin(),
    createMentionPlugin({ searchFunction: searchPeople }),
  ],
})
```

Для read-only вывода регистрируйте отдельные `InlineWidgetRenderer` через `EditorRenderer.inlineRenderers`. Runtime редактора не используется как renderer persistence API.

## Владение и безопасность

Создавайте DOM в `ownerDocument`, привязывайте listeners блока/виджета к выданному `signal`, а cleanup popup — к popup host. Нельзя восстанавливать данные виджета из произвольных DOM-атрибутов; канонический источник — `getData()`.

Результаты поиска и пользовательские labels выводятся как текст. В trusted markup sinks попадают только package-owned icons.
