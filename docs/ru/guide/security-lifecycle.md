# Безопасность и жизненный цикл

Rector очищает поддерживаемые границы содержимого, но сам редактор не является границей доверия. Считайте документы, данные буфера обмена, результаты обратных вызовов, файлы, URL и конфигурацию плагинов недоверенными, если они поступили извне текущего процесса приложения.

## Модель содержимого

Встроенные текстовые плагины хранят ограниченное подмножество HTML для внутристрочного форматирования. Общая подсистема очистки удаляет неподдерживаемые теги, атрибуты, схемы URL и свойства стилей. Встроенные рендереры повторяют очистку, потому что сохранённое содержимое могло миновать редактор.

Способ очистки зависит от контекста:

- для обычного текста используйте `textContent`;
- `sanitizeHtml()` применяйте только к поддерживаемому подмножеству форматирования;
- для ссылок и мультимедиа используйте утилиты URL Rector или явные разрешающие списки протоколов;
- для управляемых пользователем стилей разрешайте только перечисленные свойства CSS;
- не передавайте произвольный HTML в `innerHTML`, `insertAdjacentHTML` и места вставки разметки SVG.

## Доверенные типы

Rector поддерживает страницы с `Content-Security-Policy: require-trusted-types-for 'script'`. Внутренние приёмники HTML переиспользуют политику `rector` своего окна вместо политики по умолчанию. Очиститель произвольного HTML использует её только для инертного разбора и очищенного результата, поэтому не конкурирует за имя `dompurify` с независимым экземпляром приложения. Явный список директивы `trusted-types` должен разрешать `rector`; разрешите также `dompurify`, если приложение отдельно использует политику `DOMPurify` по умолчанию. Допуск `allow-duplicates` и разрешения на создание скриптов или их адресов не требуются. Прежние списки с обоими именами поддерживаются.

Rector никогда не устанавливает политику по умолчанию. `sanitizeHtml()` намеренно возвращает `string`, потому что очищенный HTML также сохраняется в данных документа и может отправляться в хранилище или по сети. Прикладной код не должен брать эту строку и напрямую присваивать её приёмнику HTML, защищённому механизмом доверенных типов. Предпочитайте построение DOM либо создавайте и отдельно проверяйте именованную политику приложения для конкретной интеграции.

Само значение доверенного типа не является решением об авторизации или доверии содержимому. Сохранённый или пользовательский HTML всё равно должен пройти подходящую очистку до передачи во внутренние вспомогательные функции Rector, работающие с доверенными приёмниками. Иконки плагинов и другая разметка, поставляемая расширениями, выполняется с тем же уровнем доверия приложения, который описан в разделе [Доверие к расширениям](#доверие-к-расширениям).

## Произвольный HTML

Блок Raw предназначен для намеренно принимаемого HTML, но и он применяет политику библиотеки для такого содержимого. Не используйте его для вывода данных администратора, встроенных сценариев, произвольных `iframe`, атрибутов обработчиков или шаблонов приложения.

Если приложению нужна более богатая вставка, создайте типизированный плагин. Пусть его данные хранят разрешённую службу и идентификатор ресурса, а рендерер строит DOM с фиксированными атрибутами.

## URL и внешнее содержимое

Разрешайте только схемы, необходимые возможности. Для большинства ссылок это `https:` и при необходимости `http:`. Отклоняйте или нормализуйте `javascript:`, опасные формы `data:`, учётные данные в URL и специальные схемы приложения, если проверенное требование явно их не разрешает.

Внешний предпросмотр, упоминания, загрузки, опросы и встраиваемые материалы должны получать структурированные данные из обратных вызовов приложения. Rector не выполняет аутентификацию таких служб, не проверяет полномочия, не ограничивает частоту запросов и не проверяет серверные правила предметной области.

## Файлы

Клиентские MIME и расширение — подсказки, а не доказательство типа. До загрузки ограничивайте количество и размер средствами приложения. На сервере проверяйте фактическое содержимое, создавайте безопасные имена, изолируйте хранилище и отдавайте файлы с правильными заголовками.

Освобождайте объектные URL расширения при завершении жизни принадлежащего ему представления. URL, полученные через `createObjectURL()` контекста вставки, принадлежат ядру: оно освобождает их при отмене или ошибке, а после фиксации сохраняет до уничтожения редактора, чтобы Undo/Redo могли восстановить мультимедиа. Не отзывайте такие зафиксированные URL при очистке отдельного блока.

## Буфер обмена

Маршрутизация вставки использует `capabilities.paste.accepts(input)` и `resolve(input, context)` определения плагина. `PasteInput` содержит `{ kind: 'text', text }` либо `{ kind: 'file', file }`. Resolver подготавливает `PasteResult` или возвращает `null`; он самостоятельно не изменяет смонтированный DOM и не фиксирует данные документа. Ядро принимает подготовленный результат через транзакцию вставки. Передавайте `context.signal` отменяемой операции и проверяйте его после завершения асинхронной работы.

Например, этот resolver принимает текстовый файл ограниченного размера и запрашивает вставку обычного текста. Результат `replacement.kind: 'text'` позволяет ядру экранировать текст для целевого поля форматированного текста.

```js
/** @type {import('@shelamkoff/rector/types').PasteCapability<{text: string}>} */
const textFilePaste = {
  accepts(input) {
    return input.kind === 'file' && input.file.type === 'text/plain'
      && input.file.size <= 1024 * 1024
  },
  async resolve(input, context) {
    if (context.signal.aborted || input.kind !== 'file'
        || input.file.type !== 'text/plain' || input.file.size > 1024 * 1024) return null
    const text = await input.file.text()
    if (context.signal.aborted) return null
    return { kind: 'rich-text', replacement: { kind: 'text', text } }
  },
}
```

Назначьте этот объект свойству `capabilities.paste` определения плагина. Проверки MIME и размера задают политику приложения, но не подтверждают подлинность файла. Сам `File.text()` не поддерживает отмену; повторная проверка сигнала отбрасывает запоздавший результат. Полные контракты схемы и возможностей приведены в разделе [Блочные расширения](/ru/guide/extensions.md).

## Доверие к расширениям

`icon` плагина, код расширения, обратные вызовы конфигурации и фабрики рендереров выполняются с правами приложения. Устанавливайте расширения как зависимости кода и проверяйте их соответствующим образом. Очистка HTML не защищает от вредоносного плагина с прямым доступом к DOM, сети или хранилищу.

Поддерживаются только пути импорта из карты `exports` пакета. Импорт внутренних файлов ослабляет границы обновления и безопасности.

## Диагностика и конфиденциальность

Встроенная служебная диагностика не содержит пользовательское содержимое. Она может включать название операции, тип плагина или блока, версии, длительность и класс ошибки. При отправке в телеметрию не добавляйте полный документ, выделенный текст, URL, имена файлов или идентификаторы пользователей.

## Жизненный цикл редактора

Редактор владеет ресурсами от успешного создания до `destroy()`:

```js
const editor = createEditor(config)

try {
  // Работа с редактором
} finally {
  editor.destroy()
}
```

При ошибке сборки Rector откатывает уже полученные ресурсы. Если ошибка возникла во время освобождения, остальные действия очистки продолжаются, а в диагностику может поступить `cleanup.failed`.

## Освобождение ресурсов расширения

Повторно используемый `BlockPluginDefinition.setup(runtimeContext)` создаёт `BlockPluginRuntime` одного редактора. Его `create(initial, context)` создаёт отдельный `BlockInstance` для каждого смонтированного вхождения. Изменяемый DOM, обработчики, наблюдатели и очистка принадлежат этому экземпляру; `BlockInstance.destroy()` вызывается без аргументов. `destroy()` среды исполнения освобождает общие ресурсы редактора. У среды исполнения внутристрочного плагина и отдельных виджетов также раздельная очистка; `destroy()` внутристрочного инструмента освобождает ресурсы его mount.

Храните состояние вхождения в замыкании `create()`. Эта фабрика принимает наблюдатель приложения, который возвращает функцию очистки и использует сигнал жизненного цикла вхождения:

```js
/**
 * @param {(element: HTMLElement, signal: AbortSignal) => () => void} watch
 * @returns {import('@shelamkoff/rector/types').BlockPluginDefinition<{label: string}>['setup']}
 */
function createLiveBlockSetup(watch) {
  return () => ({
    create(initial, context) {
      const element = context.ownerDocument.createElement('div')
      let data = { ...initial }
      let disposed = false
      element.textContent = data.label
      element.setAttribute('aria-readonly', String(context.isReadOnly()))
      const stop = watch(element, context.signal)
      const dispose = () => {
        if (disposed) return
        disposed = true
        context.signal.removeEventListener('abort', dispose)
        stop()
      }
      context.signal.addEventListener('abort', dispose, { once: true })
      if (context.signal.aborted) dispose()
      return {
        element,
        read: () => ({ ...data }),
        update(next) { data = { ...next }; element.textContent = data.label },
        setReadOnly(value) { element.setAttribute('aria-readonly', String(value)) },
        destroy: dispose,
      }
    },
    destroy() {}, // This runtime acquires no editor-wide resources.
  })
}
```

Используйте возвращённую функцию как `setup` определения. Каждое вхождение получает собственный элемент, состояние и идемпотентную очистку. Определение может использоваться несколькими редакторами; общее поле «последний отображённый элемент» смешало бы их владельцев. Наблюдатель, который выбрасывает ошибку при получении ресурсов, должен освободить уже полученную часть перед передачей ошибки дальше.

## Асинхронное изменение сохраняемых данных

Обычный сигнал жизненного цикла подходит для работы с представлением. Асинхронное изменение сохраняемых данных требует ограниченного областью владельца `DataTask`: получите его через `context.beginTask()`, передайте загрузчику `task.signal` и вызовите `task.commit(producer)` с текущими данными. Замена, уничтожение, смена поколения документа или переход в read-only отзывают задачу. Возврат к редактированию её не восстанавливает. `commit()` возвращает `false`, когда задача больше не имеет права на изменение.

```js
/**
 * @param {import('@shelamkoff/rector/types').BlockInstanceContext<{label: string, note: string}>} context
 * @param {(signal: AbortSignal) => Promise<string>} loadLabel
 * @returns {Promise<boolean>}
 */
async function refreshLabel(context, loadLabel) {
  if (context.signal.aborted || context.isReadOnly()) return false
  const task = context.beginTask()
  try {
    const label = await loadLabel(task.signal)
    if (task.signal.aborted) return false
    return task.commit(current => ({ ...current, label }))
  } finally {
    task.cancel()
  }
}
```

Функция изменения сохраняет поля, отредактированные за время загрузки. Всегда освобождайте задачу в `finally`, в том числе при ошибке загрузчика; отклонённый промис обрабатывайте в вызывающем коде приложения. Не записывайте запоздавший результат в сохранённый элемент или старый снимок данных.

## Жизненный цикл рендерера

Каждой установке должна соответствовать очистка, а каждому подключению стилей — освобождение:

```js
const renderer = new EditorRenderer()
const styleOwner = renderer.injectStyles()

renderer.renderTo(data, container)

renderer.destroy(container)
styleOwner.destroy()
```

При замене одного представления приложения другим очистка должна выполняться, даже если отображение или последующий код приложения выбросил исключение.

## Проверка уничтожения

Для каждого расширения с состоянием проверьте уничтожение:

1. до завершения асинхронного запроса;
2. при открытом всплывающем элементе или меню;
3. после многократных циклов отображения и сохранения;
4. после отмены и повтора;
5. при нескольких блоках с одним экземпляром плагина;
6. при двух редакторах или рендерерах с одинаковыми URL таблиц стилей.

После очистки не должны оставаться глобальные обработчики, наблюдатели, таймеры, кадры анимации, запросы, объектные URL, ссылки на отсоединённый DOM или стили без владельца.
