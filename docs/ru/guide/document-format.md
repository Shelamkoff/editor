# Формат документа

Rector принимает один сериализованный формат документа — `2.0.0`. Редактор, рендерер, асинхронные наборы расширений и импорт приватного буфера обмена используют одну границу текущего формата.

## Оболочка документа

```ts
interface EditorDocument {
  version: '2.0.0'
  time?: number
  blocks: BlockData[]
}
```

```json
{
  "version": "2.0.0",
  "blocks": [
    {
      "id": "p1",
      "type": "paragraph",
      "dataVersion": 2,
      "data": { "text": "Hello" }
    }
  ]
}
```

`version` и `blocks` обязательны. Отсутствующая, старая или будущая версия оболочки отклоняется до построения проекции. `time` необязателен и при наличии должен быть конечным JSON-числом.

## Данные блока

```ts
interface BlockData {
  id: string
  type: string
  dataVersion: number
  data: Record<string, unknown>
  revision?: string | number
  tunes?: Record<string, unknown>
  inline?: Record<string, EditorInlineWidget>
}
```

```ts
interface EditorInlineWidget {
  type: string
  dataVersion: number
  data: Record<string, unknown>
}
```

`id`, `type`, `dataVersion` и `data` обязательны. Идентификаторы блоков уникальны. Для зарегистрированного блока или виджета `dataVersion` должен точно совпадать с `schema.currentVersion`. Схема с текущей версией `1` не считается устаревшей. Числовой `revision` должен быть конечным.

## Данные, принадлежащие плагину

```json
{
  "id": "h1",
  "type": "heading",
  "dataVersion": 2,
  "data": { "text": "Title", "level": 2 },
  "tunes": { "textAlign": "center" }
}
```

```js
const encoded = definition.schema.encode(localData)
const decoded = definition.schema.decode({
  dataVersion: encoded.dataVersion,
  data: encoded.data,
})
```

Локальные значения при создании данных проходят через `schema.encode()`. Сериализованные значения проходят через `schema.decode()` и явно содержат точную текущую версию. Выравнивание абзаца и заголовка хранится только в `tunes.textAlign`; старый `data.align` отклоняется.

## Хранение внутристрочных виджетов

```json
{
  "data": { "text": "Hello {{mention-1}}" },
  "inline": {
    "mention-1": {
      "type": "mention",
      "dataVersion": 1,
      "data": { "id": "42", "name": "Ada" }
    }
  }
}
```

```ts
type InlineTable = Record<string, EditorInlineWidget>
```

Незарегистрированный внутристрочный тип остаётся непрозрачным и инертным. Для зарегистрированного типа точная версия схемы проверяется до вызова кода расширения. Ссылка в форматированном тексте и запись карты `inline` образуют одно логическое значение и преобразуются вместе.

## Текстовые поля с HTML

```html
<b>safe formatting</b>
```

```text
Внешний HTML очищается до превращения в канонические данные плагина.
Live-маркеры виджетов, созданные host, не являются сериализованным decoder.
```

Очистка HTML, проверка URL и защита `Trusted Types` сохраняются. Требование текущих версий не ослабляет границы безопасности.

## Проверка только текущего формата

До фиксации публичная граница отклоняет ошибочный JSON, разреженные массивы, неизвестные поля оболочки, дубли идентификаторов, отсутствующие метаданные и несовпадающие версии известных схем. Данные незарегистрированного блока с корректной текущей оболочкой сохраняются непрозрачно со статусом `unregistered`.

## Правила версий

Версия документа описывает сериализованный формат, а не версию npm-пакета. Исправляющий выпуск библиотеки сам по себе не меняет `2.0.0`. Новая версия формата задаётся явно; версии старых документов не переименовываются и не угадываются.

## Без встроенных миграций

Rector v2 не экспортирует `DocumentMigration`, `documentVersionPolicy`, цепочки миграций или режим сохранения старого документа. Если приложению нужно преобразовать исторические внешние данные, оно делает это вне Rector и передаёт полностью корректный текущий документ.

## Проверка расширений

Определения блоков и виджетов предоставляют схемы точных версий с `currentVersion`, `createDefault()`, `encode()` и `decode()`. Ошибочные данные известного типа отклоняются. Наблюдатель `onValidationError` не содержит контент; его ошибка не превращает отклонённые данные в принятые.

## Правила развития формата

Создателей и потребителей данных обновляют вместе. Версию схемы повышают при изменении её сериализованной формы, а версию документа — при изменении оболочки. Не вводите неявные версии, запасные миграции, псевдонимы совместимости или молчаливое исправление старых данных. Исторический JSON остаётся в проверках отказа или внешнем преобразователе приложения.
