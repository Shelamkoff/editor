# Rector v2 — повторная проверка Person и Carousel

Дата: 17.10.2026. Ветка: `refactor/rector-v2-architecture`. Начальный HEAD: `53bda7ece1148f060123c9fbee1dda6be700dbda`. Цель: допроверка реального поведения и стабильности, без восстановления legacy v1 API.

## Итог

В этом проходе подтверждены и устранены **два дефекта**: потеря редактируемых Person-хостов при изменениях другого человека и гонка отложенного activeIndex в Carousel. Для обоих подготовлены regression tests, код коммитится напрямую в текущую ветку. Полный паритет v1/v2 и итоговая стабильность всей библиотеки **не утверждаются**.

### PERSON-FOCUS-1 — независимое обновление Person разрушало текущий editing host (P2)

`plugins/person/index.js` выполнял `renderTabs()` и `renderBody()` на любом `update(next)`. `renderBody()` безусловно вызывал `body.replaceChildren()`, даже если активный человек не изменился, а изменился только другой человек или порядок вкладок. Поэтому пользователь, редактирующий имя/роль/bio, терял подключённый contenteditable, нативные focus и caret.

**Связанная проблема:** обработчик `input` имени замыкал прежний `tabLabel`. При оптимизации безопасного сохранения активного body вкладки всё ещё обновляются; старая ссылка на label после `renderTabs()` становилась detached, и имя в новой вкладке переставало отображать дальнейший ввод.

**Исправление**: `update(next)` сравнивает прежние и новые канонические данные именно видимого, выбранного `person.id`. При неизменности активного человека обновляются только вкладки, не DOM editing host. При изменении активного человека, удалении его ID или переходе на другой ID по-прежнему выполняется `render()` с заменой полей. Обработчик `input` имени теперь ищет живой tab label в момент ввода, а не удерживает ссылку на снятый узел.

Восстановление old v1 API, дополнительные сторы и delayed focus не вводились. Отложенная UI-ссылка исправлена вместе с изменением reconciliation, чтобы не создавать новый дефект.

**Red/green по фактическому тексту production Person definition**, исполняемому в изолированной V8-среде с DOM fixture, содержащей parent/children, focus ownership, tab query и события:
- До: **1/4 PASS**; sibling role edit, tab reorder и обновление текущей подписи не выдерживали проверку.
- После: **4/4 PASS**.
- Отдельно добавлена модель **400 последовательных изменений** других записей, состава и порядка tabs при сохранении активного `person.id`; итог **5/5 PASS**.
- Положительный контроль: когда активный человек действительно удалён, его прежние поля заменяются, и новая active Person получает правильные поля.

Коммиты: [первые три теста](https://github.com/Shelamkoff/editor/commit/5556229dd3d7ee6fd7e0e1c8a1d343519251bb7f), [тест живой подписи](https://github.com/Shelamkoff/editor/commit/223b57d1c0ed0c6327fcb1cdf77c4ac84fd1ef45), [исправление](https://github.com/Shelamkoff/editor/commit/8552fc480cb1268b1147dee7131f0bd1c9ff332b), [модель 400 изменений](https://github.com/Shelamkoff/editor/commit/e5860715cecdeceb5288937adc6cd3c46e334fd9).

### CAROUSEL-ORDER-1 — старый move continuation перезаписывал более позднюю навигацию (P2)

`plugins/carousel/index.js` в `moveSlide(from,to)` через `context.updateData()` синхронно менял порядок слайдов. Уже существующий `update(next)` пересчитывал `activeIndex` по прежнему `slide.id` и перепроецировал UI в верном состоянии. Однако `moveSlide` вдобавок ставил `queueMicrotask`, который позже **повторно** выбирал старый активный ID.

Контрольный сценарий: активный слайд A перемещён вправо, модель становится `[B,A]`. До исполнения очередного microtask пользовательский обработчик активирует B. Визуально отображается B. Устаревший microtask вновь устанавливает `activeIndex` на A, **не вызывая проекцию**. Следующая перерисовка или смена read-only режима показывает A вместо B.

Проверено на фактическом `moveSlide` из production JS с синхронным `context.updateData` и управлямой очередью microtask:
- RED: перед flush `selected=B,rendered=B`; после flush `selected=A,rendered=B`.
- GREEN: нет устаревшего deferred handler; после условного flush `selected=B,rendered=B`, порядок `[B,A]`.
- Сверено с v1 `Carousel.#move`: выбор слайда устанавливается синхронно, без позднего перезаписывания навигации.

**Исправление**: удалён исключительно избыточный `queueMicrotask` и ставший ненужным локальный `activeId` из `moveSlide`. Контракт сохранения active slide при перемещении уже реализован в `update(next)`; новый механизм не потребовался.

Коммиты: [browser regression](https://github.com/Shelamkoff/editor/commit/e5dc7aa73c47c6a7912a168453960d75d4694664), [исправление](https://github.com/Shelamkoff/editor/commit/bf541b8538ee92846994eb990c6631afc4009e6c).

### Сквозные тесты, зарегистрированные в проекте

В `tests/browser/native-plugin-parity.js` добавлены три сценария:
1. Person `blocks.update` соседней записи, сохранение field identity/caret, настоящий `printable('X')`, синхронизация tab label и Undo.
2. Person перестановка вкладок при активном поле, сохранение фокуса и дальнейший ввод.
3. Carousel перемещение активного A, более поздний публичный focus B до исходного microtask, проверка показанного слайда после read-only перерисовки.

Файл дополнительно проверен на корректность JS-синтаксиса, включая импорт исходного `pixel` fixture. Полное исполнение этих новых браузерных тестов вместе со штатным `createEditor` **не подтверждено**; факт их регистрации не следует смешивать с PASS.

### Прочие просмотренные области

Просмотрены текущие `Gallery`, `Attaches`, `Image`, `InstanceScope`, медиатаски в Carousel и shared `retainControlFocus`. Замечено, что некоторые media/projector реализации полностью перестраивают текущий view, но **автоматически объявлять все такие реконструкции багом нельзя**: от конкретной операции зависит необходимость обновления изображения, опций, управления и видимых полей. Без воспроизводимого контракта их переписывание не выполнялось.

### Ограничения вывода

Доступен только частичный локальный checkout ранее материализованных модулей; прямое скачивание полного репозитория из контейнера ограничено DNS. Целевые red/green Person осуществлены на **точном исходном тексте модуля** с DOM и dependency stubs, а Carousel — на точной функции с моделью `context.updateData`/microtask. Это не установленный пакет и не browser/npm acceptance.

Не выполнены на финальном HEAD данного прохода: полный `npm ci`, `npm test`, оба TS-конфига, `npm run test:browser` (native/CDP/IME), `test:package`, `test:docs`, heap/retention и полный дифференциальный прогон v1/v2. Исторические PASS других SHA не приписываются этому HEAD.

**Итог:** два доказанных дефекта исправлены в текущей ветке, проверены TDD/контроли, дополнительные browser cases зарегистрированы. Выпускная стабильность всей библиотеки по-прежнему требует общего локального gate.
