## Результат

Обнаружены **два подтверждённых дефекта владения DOM**, позволяющие встроенным механизмам перенести и впоследствии освободить узлы другого владельца, когда владелец представляет собой дерево, ещё не подключённое к `document`. Исправления добавляют проверку `parentNode` наряду с существующим `isConnected`. Новые классы, compatibility APIs и слои владения не вводились.

Проверенный узкий контур работает после изменений; **полную стабильность библиотеки, весь v1/v2-паритет и полный project gate этот проход не доказывает**.

### DOM-R1 — пользовательский block renderer мог украсть чужой отключённый DOM-узел (P1)

В `renderer/EditorRenderer.js` контракт требовал свежий, не подключённый `HTMLElement`. Проверялись `liveRenderedElements` и `element.isConnected`, но не `element.parentNode`.

Сценарий: приложение создаёт отключённый `section`, добавляет в него `article`; пользовательский renderer ошибочно возвращает `article`.

- `renderBlock()` принимал чужой узел как собственный.
- `render()` и `renderTo()` перемещали `article` из контейнера приложения.
- Ресурс мог позднее попасть под `renderer.destroy()` несмотря на чужого владельца.

**Исправлено:** `if (element.isConnected || element.parentNode)` отказывается принимать такой результат до получения Renderer-права владения, без вызова стороннего `destroy`. Возврат **свежего элемента без родителя** по-прежнему разрешён.

Тесты: `renderer/reentrancy.test.js`, по одному на каждый из трёх публичных методов. Изолированная исполняемая проверка на исходном implementation-модуле с DOM fixture:
- до патча: **0/3 PASS**, каждый тест правильно указывает отсутствие обязательного исключения;
- после патча: **3/3 PASS**, контейнер приложения не меняется, чужой disposer не вызывается;
- положительный контроль: свежий элемент принимается.

Коммиты: [тесты](https://github.com/Shelamkoff/editor/commit/d2e2b226e5a09f8c0b37f03f08af979a89fbe2b2), [код](https://github.com/Shelamkoff/editor/commit/44e7f9d0f149f77aad2f73d2820ada17ab088bd2).

### DOM-R2 — InlinePopupHost перемещал чужой отключённый элемент (P1)

`core/InlinePopupHost.js` запрещал `content.isConnected` и узлы редактора, но разрешал `content.parentNode !== null` в другом отключённом дереве. При `popup.appendChild(content)` такой узел удалялся из владения приложения. Также запрос мог вытеснить исправный открытый popup.

**Исправлено:** новые поверхности допускаются только при отсутствии родителя. Отказ до замены текущего popup не вызывает cleanup, который вызывающий код предложил для чужого элемента; существующая презентация сохраняется.

Тест: `core/InlinePopupHost.test.js` — отказ от захвата отключённого поддерева, сохранение исходной ноды, активного popup и списка cleanup.

Изолированное исполнение **11 настоящих тестовых функций** этого файла на исходном production-модуле с DOM/Abort adapters:
- до патча: **10/11 PASS**; падает именно новый сценарий;
- после патча: **11/11 PASS**.

Коммиты: [тест](https://github.com/Shelamkoff/editor/commit/cf00918bfed687bed044bf455624d8a429366113), [код](https://github.com/Shelamkoff/editor/commit/062ff1a6c9cb19804191e9b715d26e1d6801d412).

### Независимое браузерное подтверждение предпосылки

В реальном Chromium подтверждено, что для `document.createElement('section')`, содержащего `article`, но не добавленного в document:
`article.isConnected === false`, при этом `article.parentNode === section`. Следовательно, одна лишь проверка `isConnected` не обеспечивает владение.

### Отсеянные направления

- `core/BlockReconciler.js` **уже** отклоняет `instance.element.parentNode || instance.element.isConnected`.
- `core/InlineProjectionRuntime.js` **уже** отклоняет `root.parentNode || root.isConnected`.
- `renderer/inlineWidgets.js` **уже** отклоняет `element.isConnected || element.parentNode`.
- Встроенные Color/Mention создают отдельные popup surfaces. Их реализации прочитаны; признаков требования принимать чужие parented surfaces не обнаружено. Это анализ текущих исходников, не отдельный полный браузерный PASS.

Эти направления не исправлялись без подтверждённого дефекта.

## Ограничения приёмки

- Regression-тесты записаны в Node test files, но из-за отсутствия полного клона и зависимостей **полный `node --test` репозитория и Browser runner на этом HEAD не выполнялись**.
- Изолированный V8-прогон использовал фактический текст `EditorRenderer.js`/`InlinePopupHost.js` с точечными stub imports и контролируемой DOM-моделью. Этот результат нельзя объявлять полноценной интеграционной приёмкой.
- В изолированной проверке popup целевые и существующие 11 тестов выполнены; это не browser UI suite. Chromium использовался отдельно для нативного контракта `isConnected`/`parentNode`.
- Не запускались общий `npm test`, проектный TS 5.9.3, все native/IME/Firefox/WebKit, heap, package-consumer и docs gates. Старые отчёты о проверке других SHA не считаются результатом для этого изменения.

**Вывод:** оба подтверждённых нарушения владения DOM закрыты, негативные тесты и положительные контроли проходят в описанном ограниченном контуре. Релизную стабильность всей библиотеки до общего gate не утверждать.
